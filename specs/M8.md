# M8 – Sanity checks

## Scope
**In:** one `check` module in `hc-toolpath` that turns load Problems, `ToolpathError`s, `ToolpathNote`s and new rules into one
`Vec<Issue>`; export refuses on any Error; app: Issues panel, per-op counts, export refusal / "Export anyway?" dialogs.
**Out:** simulation (M9); collisions with clamps or fixtures; machine travel limits (there is no machine envelope in the data model, so
add it later as `Machine.travel` plus one rule); V-bit width or depth info; feeds and speeds advice beyond the unit-mix-up rule below.
The rules dropped at the end of this spec are out too.

## Crates / modules touched
- `hc-toolpath`: new `src/check.rs` (`pub use check::{check, Issue, RuleId, Severity}`), no new dependency.
- `hc-project`: move `fmt_len` from `app/src/panels.rs` to `units.rs` (`pub fn fmt_len(mm: f64, u: Units) -> String`, same text).
  Messages need it, and the app re-exports or imports it from there.
- `hc-post`: `export` runs `check` and replaces `PostError::OpFailed` and `PostError::ToolChangeBelowSafe` with `Blocked(Vec<Issue>)`.
  Update the M7 tests in `tests/golden.rs` and `tests/edge_cases.rs` that matched those variants.
- `app`: `state.rs` (`issues`, set in `refresh_toolpaths`; `open()` no longer pushes Problem messages, because they show up as Issues now;
  `problem_text` moves into `check`), `panels.rs` (Issues panel, op counts; the old per-op `Error:`/`Note:` lines go away), `main.rs`
  (export flow, two modals), `shot.rs` (`shot_issues`).

## Public API (hc-toolpath)
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum Severity { Warning, Error }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RuleId { /* the IDs in the rule table, in table order */ }

#[derive(Debug, Clone, PartialEq)]
pub struct Issue {
    pub severity: Severity,
    pub rule: RuleId,
    pub op: Option<u64>,
    pub item: Option<u64>,
    /// One sentence without the op name (the GUI adds it). Lengths and feeds via fmt_len in project units.
    pub message: String,
}

/// `toolpaths` = the output of `generate(project)` (enabled ops, user order). Pure and deterministic.
pub fn check(project: &Project, toolpaths: &[(u64, Result<Toolpath, ToolpathError>)]) -> Vec<Issue>;
```
`check` calls `project.validate()` itself. Output order: project-level issues first, then ops in user order; within an op, table order,
then item order in `op.items`. Op rules run on **enabled** ops only (disabled ops are not exported; they are checked once enabled).
TOL = 1e-6 mm.

**No duplicates.** `ToolpathError::MissingTool`/`MissingItem` are skipped, because the Problems already report every case, not just the
first one. `InvalidParam("clearance_z" | "safe_z")` is skipped, because `InvalidMachine` reports it once instead of once per op. Notes
map 1:1.

**When a rule runs.** "op" rules need only the op and its tool (tool found). "tp" rules also need `Ok(toolpath)`, so the geometry is
known to be valid. SharedEdge runs on the op's existing items even when the pocket fails, because a misclassified island can
make generation fail too. An op with an Err therefore shows its error plus the op-level rules (e.g. flute length), never geometry noise.

| 19 | TabsNotThrough | W | op | Contour, tabs enabled, `op.depth < thickness − TOL` (the tabs only leave bumps) | Tabs are enabled but the cut does not go through the stock |
| 20 | TabTooHigh | W | op | Contour, tabs enabled, `tabs.height >= op.depth − TOL` (nothing is cut under the tabs) | Tab height 3.000 mm is not below the depth 2.000 mm |
| 21 | TabsReduced | W | tp | `ToolpathNote::TabsReduced` | Item 7: only 2 of 4 tabs fit |
| 22 | TabsOnOpenContour | W | tp | `ToolpathNote::TabsOnOpenContour` | Item 4 is open: no tabs |
| 23 | NoTabsThroughCut | W | tp | Contour (any side), closed item, `depth >= thickness − TOL`, and tabs disabled or `tab_positions(..).0` empty; per item. Inside: "The cut-out piece may come loose". Outside/On: "The part may come loose" | The part may come loose: through-cut without tabs |
| 24 | TabOnCorner | W | tp | Contour with tabs, closed item: a tab interval [s − w/2, s + w/2] on the item (s = position × length, wraps) contains a segment junction where the tangent turns by > 30°. Tangent-continuous arcs (circles, rounded corners) do not count. One issue per tab | Tab 2 sits on a corner and may be weak or misplaced |
| 25 | DrillSize | W | tp | Drill op, circle item: \|2·radius − tool.diameter\| > 0.05 mm (points have no size: skipped) | Hole Ø15.875 mm, drill Ø16.000 mm |
| 26 | SharedEdge | W | op (existing items) | Pocket: a segment midpoint of closed item A lies within 1e-6 mm of another closed item B of the same op. One issue per (A, B), item = A. This is the gouge risk from a misclassified island (M5 ruling e) | Item 9 shares an edge with item 8: the pocket may cut into it |

An Outside contour on an auto-fitted stock puts the centre exactly r outside the stock, which is fine; more than that means the tool cuts beside the stock | Cuts up to 12.000 mm outside the stock |

`TabOnCorner` tangents: a private helper in `check.rs` (line: end − start; arc: perpendicular to the radius, signed by the sweep). It is
needed only there, so it does not go into hc-geom.

## Dropped rules (and why)
- Depth per pass > depth: harmless, `depth_levels` makes one pass.
- Tab on an **arc**: on a round part every tab is on an arc and is fine. Only real corners are flagged (rule 24).
- Duplicate or overlapping manual tabs: the intervals merge, so this is harmless (M6 ruling 4).
- Tab projected onto the wrong wall in a narrow neck: the distance test (d > r) also fires at every concave corner, which gives false
  positives. The canvas marker plus the M9 simulation show the problem.
- Same item in two ops with overlapping cuts: usually intended (pocket + contour, engrave + contour).
- Repeated tool change (same tool in two segments): often intended (engrave first, contour last), and the file count already shows it.
- Feed "implausible" in absolute terms: depends on the machine, and there is no envelope.

## Timing
`AppState::refresh_toolpaths` sets `self.issues = check(&self.project, &self.toolpaths)` whenever it regenerates, so the check is live
and costs no extra regeneration. `export` runs `generate` + `check` again, so it never trusts stale state.

## hc-post
```rust
pub enum PostError { UnknownPost(String), NothingToExport, Blocked(Vec<Issue>) /* Errors only, check order */, BadToolpath(u64) }
// Display Blocked: "Cannot export: 2 errors. First: Contour 1: Tool too large for item 17"
```
Order in `export`: `post_for` → `generate` → empty → `NothingToExport` → `check`; any Error → `Blocked`. After that, an `Err` toolpath is
impossible; keep `BadToolpath(id)` for it and for the existing finite/first-move guard.

## GUI
- **Issues panel:** `egui::Panel::bottom("issues")` above the status bar, shown when `issues` is non-empty, resizable, with a scroll area,
  heading `Issues (n)`. One `selectable_label` per issue: `"Error · Contour 1 · Tool too large for item 17"` (the severity word in
  `error_fg_color` / `warn_fg_color` through a `LayoutJob`; no icons or glyphs). The label text is the accessible name. Click:
  `select_op(op)` and, if `item` is set, `selection = {item}`. An issue with no op only shows. Project-level issues use `Project` in
  place of the op name.
- **Operations list:** under each op, in place of the M5/M6 `Error:`/`Note:` lines, show `"1 error, 2 warnings"` (omit zero parts, show
  nothing when clean) in the error colour when it has errors, else the warn colour.
- **Export (`App::export_gcode`):** `refresh_toolpaths`, then: any Error → modal "Cannot export G-code" listing the errors (same
  text as the panel) plus an `OK` button; no file dialog. Only warnings → modal "Export anyway?" listing them, with the buttons
  `Export anyway` and `Cancel`; confirming continues to the existing `gcode()` + file dialog. Clean → as in M7. State:
  `App.export_prompt: Option<Severity>` (cleared by any button or Escape).

## Risks
- `FeedVsTool` and `ThroughCut` thresholds (4×, 1 mm) are judgment calls. They are constants in `check.rs`; document them in the M11
  "sanity messages" chapter.
- Live check cost: `TabOnCorner`/`NoTabsThroughCut` call `tab_positions` again (cheap); `SharedEdge` is O(segments²) per pocket. It is
  fine for DXF-sized jobs; it rides on the same regeneration shortcut as M5.
- Removing `PostError::OpFailed`/`ToolChangeBelowSafe` breaks M7 tests by design. Update them, don't keep the old variants alongside.
- Test 28 depends on the real Bracket geometry (e.g. auto tabs landing on corners). If it fails, look at the rule first.

## Orchestrator amendment (2026-10-26)

A1. "No tabs on a through-cut" warns for **Outside** (and closed On) contours only. Inside through-cuts
    without tabs are not reported: the loose piece is normally the waste slug of a hole, and a warning on
    every contoured hole would be noise. Adjust that rule's +/− tests accordingly.

## Architect review of the implementation (2026-10-26)
State: 465 pass and 2 fail (both duplicates, see 1). The rules, API, timing, hc-post `Blocked` and GUI all match the spec plus A1.
No spec items are missing.

**Rulings**
1. Duplicate issues: **must-fix, in `Project::validate`** (root cause; it is also the load API). One `DuplicateToolId` per tool id
   (a `reported` set, like the id loop) and one `MissingItem` per (op, item). The existing hc-project tests use a single duplicate and
   stay green. `check` stays a plain mapping.
2. Blocked text uses the op id: **accept**. The GUI path always shows the modal with op names first, so the Display text only shows
   up in the rare fallback message. The `shortcut:` comment is already there.
3. Item ids in messages: **must-fix**. The user never sees ids. Add one `describe(project, id) -> String` in `check.rs`:
   `circle Ø15.875 mm on layer Outline`, `closed contour on layer Outline`, `open contour on layer Outline`, `point on layer Outline`,
   and for a missing item `a deleted item (id 999)`. Use it in every message that names an item. Rules 10–12, 21 and 22 get their own
   text in `check` (not `e.to_string()` / `n.to_string()`), e.g. "Tool too large for the circle Ø15.875 mm on layer Outline". The
   `ToolpathError`/`ToolpathNote` Display texts stay as they are (other callers, tests). Tests that match "item N" text update.
4. False positives:
   a. DrillSize: **change**. Warn only when `tool.diameter > hole + 0.05 mm` (an oversize hole ruins the part). Smaller drills are tap,
      pilot or clearance cases and an undersize hole can still be fixed. Tests: + Ø5.1 bit on a Ø5 hole; − Ø4.2 bit on a Ø5 hole;
      − Ø5.04.
   b. NoTabsThroughCut on closed On / held-down Outside: **keep** (A1 scope). Only a warning; we cannot tell part from slug for On,
      and the safer default wins.
   c. FeedVsTool: **change to 10×**. 25.4× mix-ups are still caught, 1/5 for aluminium is silent. Tests: + 600×25.4; − 600×9.
   d. OutsideStock on a deliberate overhang: **keep**. It is rare, only a warning, and the stock is usually wrong.
   e. StepoverHigh at 50 %: **keep**. `pocket_rings` has no final centre pass: ring k cuts the band offset ± r and the last ring sits
      less than one step from the centre line, so a centre strip stays uncut once step > r, i.e. stepover > 50 %. Straight walls are
      not the issue. The message stays as it is; format the value with `{:.0}`.
   f. SharedEdge on two touching rectangles: **change**. Report the pair only when one item's bbox contains the other's
      (`BBox::contains_bbox`, i.e. nested = island case). Side-by-side pockets are pocketed separately and are fine. Tests: + inner
      square sharing two edges; − the L made of (10,10)–(25,40) and (25,10)–(40,25).
   g. Feed 0 → InvalidValue + FeedVsTool: **must-fix**. FeedVsTool only for finite `v > 0` (InvalidValue covers the rest).
5. Coder deviations: **accept all**. One issue per unordered pair; OutsideStock reports the cutter edge's overshoot (more useful than
   the centre's); the message wordings; a click outside the export modal closes it (the same as OK / Cancel, never exports).
