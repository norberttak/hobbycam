HobbyCAM M21 - collapsible Layers / Operations pane

Mock of today's main window (M18 option B3, light): tile sidebar, Layers + Operations pane, canvas, Properties (shown because Contour 1 is selected), Issues, status bar. Each option shows the expanded and collapsed state side by side. The mocks are live: click a strip or a tab to toggle it; in C click the canvas to close the flyout. Hover the tiles for their names.

Widths quoted are for a 1280 x 800 window, measured on docs/src/images/main-window.png: sidebar 110 px (SIDEBAR_W), Layers/Operations pane about 300 px (the op rows with Up/Down/Delete widen it past the 260 px default), Properties about 260 px. Strip = 22 px. Icons come from a pinned CDN for this mock only.

What applies to every option

  • Remembered state: per computer, in prefs.json, like M20's snap settings: new bool fields on hc_project::Prefs (default true = open, as today). The struct is #[serde(default)], so an old prefs.json still loads and PREFS_FORMAT_VERSION stays 1. Written through set_prefs as the Settings snap checkboxes are. The pane width stays egui's own memory as it is today.
  • Operation selected while collapsed: Properties is a separate pane, so it still shows the op's fields (name, tool, depths, feed, tabs ...); nothing changes there. Only the Up/Down/Delete/enable controls and New operation need the pane open.
  • Issues panel: clicking an issue already selects the op and its geometry, and Properties shows the op. Proposal: do not auto-expand (a pane that opens on its own moves the canvas under the mouse). Cheap extra: an amber dot on the strip / Operations tab when any op has an issue (shown in the mocks), so a collapsed pane does not hide the per-op warning lines.
  • Keyboard / menu: View menu gets checkable item(s) that do the same as the strip. No single-letter keys (L, R, C, T, O, F, M are tools); Cmd+B / Cmd+1 / Cmd+2 / Cmd+3 are free today.
  • Tests: kittest by label (query_by_label("Hide Layers and Operations")) needs response.widget_info(..) on the painted strip, same as the M18 tiles; the rotated text itself is not visible to kittest/screen readers.
  • Dark theme: the strip uses only Visuals colours (window_fill, widgets.hovered.bg_fill, selection.bg_fill), so it follows dark mode with no extra palette. Not mocked.
