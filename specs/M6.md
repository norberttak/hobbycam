# M6 – Holding tabs

## Scope
**In:** tab placement (auto Count/Spacing + manual per item), lifting the tool over tabs in Contour toolpaths, non-fatal toolpath notes,
project format v2 (manual tab positions) with a v1→v2 migrate, tab settings in the op properties panel, tab markers on the canvas with
select / drag / delete / add, a screenshot.
**Out:** G-code (M7), sanity warnings (M8, list below), ramped/triangular tabs (later shortcut: replace the vertical up/down with a ramp
of length `height / tan(angle)` inside the gap), tabs on Engrave/Pocket/Drill, tab display in the toolpath view (lifted moves look the same
from the top; Z colouring is M9), undo.

## Which ops get tabs
Only `OpKind::Contour` (Inside/Outside/On) on **closed** contours. `op.tabs` is ignored for Engrave, Pocket, Drill (the UI shows the tab
section only for Contour). Contour **On** with tabs enabled on an **open** contour: no tabs for that item, the op still succeeds, and the
toolpath gets `ToolpathNote::TabsOnOpenContour(item)`. M8 turns notes into warnings.

## Crates / modules touched
- `hc-geom` `segment.rs`, `contour.rs`: arc-length helpers.
- `hc-project` `project.rs` (`ManualTabs`, `Tabs.manual`, `remove_item`), `io.rs` (v2, migrate, separate library version), `tool.rs`.
- `hc-toolpath`: new private module `tabs.rs` (placement, projection, start rotation, interval cutting); `lib.rs` (`cut_pass`, notes, validation).
- app: `state.rs`, `canvas.rs`, `panels.rs`, `shot.rs`.

## Public API
```rust
// hc-geom. d = distance along a segment from its start, s = distance along a contour from its start (both mm).
impl Segment {
    pub fn point_at(&self, d: f64) -> Point;              // d clamped to [0, length]
    pub fn split_at(&self, d: f64) -> (Segment, Segment); // 0 < d < length; an arc stays an arc: same center/radius,
                                                          // sweeps sweep·d/len and the rest, 2nd start_angle = 1st start + 1st sweep
    pub fn closest(&self, p: Point) -> f64;               // d of the nearest point
}
impl Contour {
    pub fn point_at(&self, s: f64) -> Point;              // closed: s taken mod length; open: clamped
    pub fn closest(&self, p: Point) -> (f64, f64);        // (s, distance) of the nearest point; the first segment wins ties
}
// Segment::distance_to becomes p.distance(self.point_at(self.closest(p))) (no duplicate math).

// hc-project
pub const FORMAT_VERSION: u32 = 2;          // project
pub const LIBRARY_FORMAT_VERSION: u32 = 1;  // tool library schema is unchanged, so it is not bumped
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct ManualTabs { pub item: u64, pub positions: Vec<f64> }  // fractions of the ITEM contour length, [0,1), from the item's
                                                                   // start in its stored direction; order = insertion order
pub struct Tabs { pub enabled, pub placement, pub width, pub height, #[serde(default)] pub manual: Vec<ManualTabs> }
pub fn migrate(value: Value, found: u32) -> Result<Value, ProjectError>; // project only; found < 2: every operations[].tabs gets
                                                                          // "manual": [] (a missing tabs object stays a JSON error, as in v1)
// from_versioned_json gains (supported: u32, migrate: fn(Value, u32) -> Result<Value, ProjectError>); the library passes
// LIBRARY_FORMAT_VERSION and an identity fn.

// hc-toolpath
pub struct Toolpath { pub op_id, pub tool_id, pub rpm, pub moves, pub notes: Vec<ToolpathNote> }
#[derive(Debug, Clone, PartialEq)]
pub enum ToolpathNote {
    TabsReduced { item: u64, placed: usize, requested: usize }, // "Item 7: only 1 of 4 tabs fit"
    TabsOnOpenContour(u64),                                      // "Item 7 is open: no tabs"
}
impl Display for ToolpathNote {}
/// Tab centres on `item` as fractions (see ManualTabs) and an optional TabsReduced note. Manual entry for item_id → its positions
/// verbatim (no note). Used by the toolpath and by the canvas markers, so both always agree.
pub fn tab_positions(item: &Contour, tabs: &Tabs, item_id: u64, tool_diameter: f64) -> (Vec<f64>, Option<ToolpathNote>);
```
Validation (Contour op with `tabs.enabled`, after the existing op checks, → `InvalidParam`): width not finite or ≤ 0 → `"tab_width"`,
height → `"tab_height"`, Spacing distance → `"tab_spacing"`, any manual position not finite → `"tabs"`. Positions are used `rem_euclid(1.0)`.
Count 0 = no tabs, no note.

## Geometry
Let D = tool diameter, w = `tabs.width`, h = `tabs.height`, L = item length.
- **Width** = material bridge measured along the part edge. The lifted interval on the tool-centre path has length **g = w + D**, centred on
  the projection of the tab centre onto the path (the tool still cuts r on each side of the interval). Exact on straight edges for
  Inside, Outside and On. On arcs the bridge differs (offset path radius R±r vs part radius R); accepted, auto placement avoids arcs.
- **Projection:** tab centre P = `item.point_at(t·L)`; nearest point (`Contour::closest`) over all loops of that item's cut paths (offsets can
  give several loops); its s on that loop is the interval centre. Positions live on the item, so they survive tool, side and direction changes.
- **Height** from the final depth up: tab top `z_tab = min(−depth + h, 0)` (never above the stock top). A pass at z lifts only if `z < z_tab − 1e-9`; other passes are unchanged.
  h ≥ depth means every pass lifts (M8 warns).
- **Profile** (rectangular, v1), at a lifting pass, interval [a, b] on the path: cut to a at z, `Linear(A @ z_tab, plunge_feed)` (vertical
  up), the path between a and b at z_tab with `op.feed` (lines stay Linear, arcs stay Arc), `Linear(B @ z, plunge_feed)` (vertical down,
  it plunges into uncut material), continue. All feed moves, **no rapids**: the M5 rapid invariant (test 10) holds unchanged, and every
  Z-lowering Linear is still vertical at plunge_feed.

## Auto placement (on the item, deterministic)
1. Requested n: `Count{count}` → count; `Spacing{d}` → `max(1, ceil(L/d − 1e-9))`.
2. Capacity: `min_pitch = w + 2D`; `n_max = floor(L / min_pitch)`. If n > n_max, n = n_max and note `TabsReduced{placed: n_max, requested}`.
3. Nominal s_k = L·(k + 0.5)/n, k = 0..n.
4. Zones: margin m = w/2 + D (gap half plus r on each side, so inside offsets with shorter edges still fit). Every **Line** with
   length ≥ 2m gives zone [s_seg + m, s_seg + len − m]. No zone (circles, all-arc shapes) → keep the nominals (arcs as fallback).
5. Snap each s_k to the nearest zone point (circular distance on closed contours); tie within 1e-9 → the zone first in contour order.
6. Walk in k order; drop a tab closer (circular) than min_pitch to a kept one. If any is dropped, the note's `placed` is the kept count.
Arcs, short lines and corners are thus avoided whenever a long straight line exists.

## Splitting and the loop start (in `tabs.rs`)
- Intervals [s − g/2, s + g/2] mod path length P; overlapping ones are merged (manual tabs may overlap). Union covering ≥ P − 1e-6
  → `InvalidParam("tabs")`.
- **Start rule:** if the path start lies strictly inside any interval (an interval wraps past s = 0), the closed path is rotated to start
  at the middle of the longest free gap (split the segment there with `split_at`). Then no interval wraps and the plunge is never in a tab.
  Otherwise the M5 start is kept. Done before `split_large_arcs` and before ordering (the feature start changes).
- Cutting: walk segments with cumulative s; split at a and b with `split_at` (skip a split within 1e-6 of a segment end, no zero-length
  moves). An interval may span several segments, lines and arcs. Arc pieces keep the exact center and radius.
- `cut_pass(out, path, z, feed, lift: Option<(&[(f64, f64)], f64, f64)>)` = (intervals, z_tab, plunge_feed). `groups` carry
  `(Contour, Vec<(f64, f64)>)` per path; Pocket/Engrave pass empty intervals. M5 re-entry/ordering logic is unchanged.

## App
- `Project::remove_item` also drops `ManualTabs` for that item. Stale entries for items no longer in the op are ignored (kept in the file).
- `AppState.selected_tab: Option<(u64 /*item*/, usize /*index*/)>`; cleared on op selection change, project replace, Escape.
- `AppState` methods (all on `selected_op`, Contour with tabs enabled, else no-op; set dirty; regen happens via the project compare):
  `tab_at(p, tol) -> Option<(u64, usize)>`, `add_tab(item, p)`, `move_tab(item, idx, p)`, `delete_tab(item, idx)`, `reset_tabs(op)`.
  The first edit on an item without a manual entry **materializes** the current `tab_positions` into one, then edits it. New/moved
  position = `closest(p).0 / L`. `reset_tabs` clears `manual` for the op ("Reset to auto").
- Canvas, selected op only: for each closed item, a 4 px segment from `point_at(s − w/2)` to `point_at(s + w/2)` plus a 5 px dot at s,
  tab colour (theme-aware teal), selected tab in `SELECTED`. Input priority: press on a tab (within `PICK_PX`) → select it and drag it
  along the contour (`move_tab` every frame; no box select); click on a tab → select it; other clicks unchanged (clear `selected_tab`);
  double-click within `PICK_PX` of a closed item of the op → `add_tab` (the first click of it may change item selection: accepted);
  Delete/Backspace (when egui does not want the keyboard) with a selected tab → `delete_tab`.
- Op properties, Contour only: "Tabs" group: Enabled checkbox, Count (DragValue 0..=100) / Spacing (`length_field`) radio, Width, Height
  (`length_field`), "Reset to auto" button (enabled when the op has a manual entry), hint "Double-click the contour to add, Del removes".
- Operations list: `Ok` with notes → one line per note in the warning colour: `Note: <Display>`.

## For M8 (tab-related sanity rules)
Tabs enabled but depth < stock thickness (not cut through; PLAN); h ≥ depth (tab is the full depth: nothing gets cut there); any
`ToolpathNote` (reduced count, open contour); a tab centre on an arc (fallback placement or manual); manual tabs whose gaps overlapped
(merged); tabs enabled with 0 tabs on an Outside contour (part will come loose).

## Risks
- Nearest-point projection on Inside paths of concave shapes may pick a different wall when a manual tab sits near a narrow neck. The
  marker on the item shows where the user put it; toolpath display shows nothing different. M8 may compare projection distance with r.
- egui double-click also delivers a click first; item selection may change on add. Accepted for v1.
- Bridge width on arcs is approximate (see Geometry). Documented in M11 user docs.
- Dragging regenerates every frame (M5 risk, same upgrade path).

## Architect review of the implementation (2026-10-26)
State: tester green (334 tests). Spec tests 1–14 are present, and the API matches the spec.

**Rulings on the tester/coordinator items**
1. Manual tab exactly on a sharp corner of an Outside path (projection = the corner arc's centre, the result depends on direction):
   **accept**. Every point of that arc and the adjacent line ends are equidistant, so a "middle of sweep" rule in `Segment::closest`
   would not settle the `Contour::closest` tie anyway. The tab lands at one end of the corner arc. M8: warn on a tab centre at an arc/corner.
2. h > depth: **must-fix**. `z_tab = min(−depth + h, 0)` (spec updated). Add a test: depth 2, h 3 → the lifted moves are at Z 0.
3. v1 file without a `tabs` object → JSON error: **accept**. M3 always wrote tabs. Spec text corrected (it wrongly said serde default).
4. Out-of-range/duplicate manual positions load without a Problem: **accept**. `rem_euclid` and interval merging make them harmless. M8 may note duplicates.
5. move_tab/delete_tab with an out-of-range index materializes auto → manual and sets dirty: **must-fix**. Check the index against the
   current positions (`tab_markers`) before `edit_tabs`. An out-of-range index is a no-op: no manual entry, not dirty.
6. delete_tab leaves `selected_tab` pointing at another tab after a lower index is deleted: **must-fix** (bug). Same item and
   selected index > idx → decrement; == idx → None. Add a test.
7. Empty manual entry = 0 tabs, no note: **accept**. This is the M8 rule "0 tabs on an Outside contour".
8. Selected tab marker uses the same orange as the selected contour: **must-fix** (cheap). Delete acts on it, so it must be visible.
   Draw the selected tab with a 7 px dot and a 2 px outline in the text colour (`ui.visuals().text_color()`), still in `SELECTED`.
9. Red line at Y = 0: **accept, not a regression**. It is the X axis (1 px red at 60 %, green for Y), drawn since M4 in the grid
   section of `canvas.rs`, which this diff does not touch. Earlier shots had the origin off-screen or under the grid line.

**Coder deviations:** "Tabs enabled" label, switch defaults Spacing 100 / Count 4, `add_tab` selects the new tab: all **accepted**.

**Other findings**
- No spec items missing.
- Logic: `tabs.rs` merge / wrap / start rotation / `split_pieces` and `cut_pass` look correct. A lift interval ending exactly at the path
  end gives a vertical down move at the end, then the next level plunges there: correct. No other bugs found.
- Cosmetic (acceptable, fix in passing): in `hc-toolpath/src/lib.rs`, `type Lift` sits between two `use` lines (same as M5 finding 2).
- Acceptable: `cut_pass` gets `lift` as `Option` though every caller passes `Some` (empty intervals mean no lift). The spec asked for
