# M18 – UI refresh (option B3: colour tiles, selected = dark ring + marker)

Branch `feature/ui-refresh`. Crate touched: `app` only. No project / library format change, no new crate dependency.
The user picked **B3** from `specs/M18-mockup.html` (committed with this milestone): Phosphor **fill** icons in white
on rounded tiles coloured per sidebar group, B palette for light and dark, disabled = grey tile with a muted icon,
selected = solid tile + 2.5 px panel-coloured gap + 2.5 px dark ring + a small filled arrow on its left.

## Scope
**In:**
- Swap the bundled icon font `Phosphor.ttf` (regular) for `Phosphor-Fill.ttf` (same package, same release, same codepoints).
- New module `app/src/theme.rs`: hex palette, per-group tile colours, pure `tile_style`, `visuals(dark)`, `CanvasPalette`.
- `panels.rs`: the sidebar button becomes a painted tile widget; spacing/width adjusted so ring and marker are not clipped.
- `main.rs`: install light and dark `Visuals` once (next to the font install); OS theme following keeps working.
- `canvas.rs`: hard-coded selection / snap / toolpath / rapid / stock / grid colours come from `CanvasPalette`.
- Tests, docs text (`interface.md` sidebar paragraph), all `docs/src/images/*.png` regenerated, CHANGELOG, README, assets README.

**Out (explicitly):** user-selectable themes or a theme setting; custom icon art; per-icon colours other than the group
colour; changing the menu bar / status bar to a different fill than the other panels (egui panels share `panel_fill`);
changing ACI layer colours (`aci.rs`, incl. colour 7 using egui's default text colour); origin red/green, tab teal,
simulation depth colours, box-select blue/green (window/crossing convention); tooltips or accessible names; icons in
menus; animations; a dark-mode docs screenshot.

## Decisions
1. **Fill font replaces regular, regular is deleted.** Icons appear only in the sidebar; nothing else needs the
   regular weight. Shipping both costs 489 KB for no use. All 23 codepoints were checked against
   `src/fill/style.css` of 2.1.2: identical, so `icons.rs` constants do not change. Same MIT licence file.
2. **Tile 36 × 36 allocated, glyph 22 pt, corner radius 8** (review amendment: 40 px tiles overflowed by 38 px with
   Simulation + Issues open at 1280 × 800). Ring and marker are painted outside the allocation. `in_sidebar` is
   widened to `height >= 32` so it does not sit on the exact tile height.
3. **Spacing grows to make room for ring and marker** (no clipping, no overlap even when Show toolpaths and
   Simulation, which share a row, are both selected): column gap 18, row gap 6, 4 px extra left padding, 6 px top and
   bottom padding. `SIDEBAR_W` 100 → 110. Row gap stays 6 (> the 5 px ring: `Rect::intersects` is inclusive, so 5 would
   make the ring test fail) and the separators stay. Measured at 1280 × 800 with Simulation + Issues open: last tile
   bottom 635, panels top 650 (content incl. 6 px bottom padding ends at 641 < 648 viewport: no scrolling).
4. **Group colour from the action, not a new field:** `SideEntry::tint()` matches on `SideAct` (exhaustive, the
   compiler catches a new action). Set origin and Zoom to fit are `View` (green) though they sit in the draw group,
   exactly as in the mock-up.
5. **Ring and marker colour = the B palette `head` colour** (`#0F172A` light, `#F8FAFC` dark) – the mock-up's
   `.optB3` uses `var(--head)`, the darkest/lightest text colour; "text colour" in the brief means this.
6. **Disabled tiles are painted at full opacity** (`painter.set_opacity(1.0)` on a clone of the disabled ui's
   painter), as the mock-up: grey tile `btn` + `muted` icon. Otherwise egui would fade the grey tile a second time.
   `ui.add_enabled` stays, so disabled = no click, and accesskit / tooltips behave as today.
7. **Visuals = `Visuals::light()` / `Visuals::dark()` with B colours overridden**, installed with
   `ctx.set_visuals_of(Theme::Light, ..)` and `(Theme::Dark, ..)` once; the OS theme switch then picks the right one.
   One palette source (`theme.rs`); the canvas background is `extreme_bg_color` (= B `canvas`), text fields get
   B `input` via `text_edit_bg_color`.

## API – `app/src/theme.rs` (add `mod theme;` in `main.rs`)
```rust
use eframe::egui::{Color32, Stroke, Visuals};

const fn hex(rgb: u32) -> Color32 { Color32::from_rgb((rgb >> 16) as u8, (rgb >> 8) as u8, rgb as u8) }

/// Sidebar tile colour group.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Tint { Draw, View, Edit, File, Ops, Set }

/// B palette, one per theme (values in the table below).
pub struct Palette {
    pub win: Color32, pub panel: Color32, pub accent: Color32, pub text: Color32, pub head: Color32,
    pub muted: Color32, pub border: Color32, pub btn: Color32, pub input: Color32, pub rowsel: Color32,
    pub canvas: Color32,
}
pub const LIGHT: Palette = Palette { .. };
pub const DARK: Palette = Palette { .. };
pub fn palette(dark: bool) -> &'static Palette;

pub fn group_color(t: Tint, dark: bool) -> Color32;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct TileStyle {
    pub fill: Color32,
    pub icon: Color32,
    /// Selected: (gap colour = panel, ring colour = head).
    pub ring: Option<(Color32, Color32)>,
}
pub fn tile_style(t: Tint, dark: bool, enabled: bool, selected: bool, hovered: bool, pressed: bool) -> TileStyle;

/// Each RGB channel × f, saturating at 255 (CSS `brightness()`); alpha 255.
pub fn brightness(c: Color32, f: f32) -> Color32;

pub fn visuals(dark: bool) -> Visuals;

/// Canvas colours not covered by Visuals.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct CanvasPalette {
    pub grid_minor: Color32, pub grid_major: Color32, pub selected: Color32, pub snap: Color32,
    pub feed: Color32, pub muted: Color32, // rapids + stock outline
}
pub fn canvas_palette(dark: bool) -> CanvasPalette;
```

### `tile_style` rules
- `!enabled` → fill = `btn`, icon = `muted`, ring = `None` (hover/pressed ignored).
- enabled → fill = group colour, then `pressed` → `brightness(fill, 0.88)`, else `hovered` → `brightness(fill, 1.12)`;
  icon = `Color32::WHITE`.
- ring = `Some((panel, head))` iff `enabled && selected`.

## `panels.rs` changes
```rust
/// Gap between the two button columns (room for the selected ring and the arrow of the right column).
const SIDEBAR_COL_GAP: f32 = 18.0;
/// Gap between rows (room for the 5 px ring).
const SIDEBAR_ROW_GAP: f32 = 6.0;
/// Extra left padding so the left column's arrow is not clipped.
const SIDEBAR_PAD_LEFT: f32 = 4.0;
/// Two tiles, the column gap, the extra left padding and the panel margins (8 px each side) = 110.
pub(crate) const SIDEBAR_W: f32 = 2.0 * TILE + SIDEBAR_COL_GAP + SIDEBAR_PAD_LEFT + 16.0;
pub(crate) const TILE: f32 = 36.0;

impl SideEntry { pub(crate) fn tint(&self) -> theme::Tint /* match self.act, table above */ }
```
- `sidebar_buttons`: `item_spacing = vec2(SIDEBAR_COL_GAP, SIDEBAR_ROW_GAP)`; wrap the content in
  `egui::Frame::NONE.inner_margin(egui::Margin { left: 4, right: 0, top: 6, bottom: 6 })` (inside the ScrollArea);
  `side_button` gets the extra argument `tint: theme::Tint` (pass `e.tint()`).
- `side_button` keeps `let r = ui.add_enabled(enabled, side_widget(glyph, tint, selected.unwrap_or(false)));` and
  `side_info(..)` **unchanged** (same `widget_info`, same tooltips).
- `side_widget(glyph, tint, selected) -> impl egui::Widget` (closure `move |ui: &mut Ui| { .. }`):
  1. `let (rect, r) = ui.allocate_exact_size(vec2(TILE, TILE), Sense::click());`
  2. if `ui.is_rect_visible(rect)`: `let st = theme::tile_style(tint, ui.visuals().dark_mode, ui.is_enabled(),
     selected, r.hovered(), r.is_pointer_button_down_on());`
     `let mut p = ui.painter().clone(); p.set_opacity(1.0);` (decision 6)
  3. `p.rect_filled(rect, 8, st.fill)`; glyph: `p.text(rect.center(), Align2::CENTER_CENTER, glyph,
     FontId::proportional(22.0), st.icon)`.
  4. `if let Some((gap, ring)) = st.ring`: `p.rect_stroke(rect, 8, Stroke::new(2.5, gap), StrokeKind::Outside)`;
     `p.rect_stroke(rect.expand(2.5), 10, Stroke::new(2.5, ring), StrokeKind::Outside)`; marker
     `p.add(Shape::convex_polygon(vec![pos2(l - 6, cy), pos2(l - 11, cy - 5), pos2(l - 11, cy + 5)], ring,
     Stroke::NONE))` with `l = rect.left()`, `cy = rect.center().y` (5 wide, 10 tall, tip 1 px off the ring).
  5. keyboard focus (`r.has_focus()`): `p.rect_stroke(rect, 8, Stroke::new(2.0, ui.visuals().hyperlink_color),
     StrokeKind::Inside)` (accent; drawn over the tile, so it shows with or without the ring).
  6. return `r`. `Sense::click()` is focusable, so Tab + Space/Enter click it as egui buttons do.
- Hover brightness only applies while the tile is enabled (`tile_style` ignores it otherwise).

## Risks
- **Vertical fit:** covered by test 13a. A future sidebar row (+42 px) will break it at 1280 × 800 with
  Simulation open; the next lever is `ui.add(egui::Separator::default().spacing(0.0))` (−24 px), not the row gap.
- **First-frame look:** visuals are set inside the first `show`, so frame 1 is drawn with egui defaults (same as the
  font today). Harmless; shots run several frames.
- **Disabled opacity override** (`set_opacity(1.0)`) also ignores any outer fade; there is none in this app.
- **Contrast:** white on the dark `File` `#475569` / `Set` `#52525B` tiles is fine (≥ 7:1); white on light `Ops`
  was ~2.8:1 with the mock-up's `#F97316`; after review the user approved `#EA580C` (~3.6:1, same as dark).
  Do not change hexes without asking.
- **Canvas 18 px narrower:** tests that click fixed screen points use (640, 400) / (700, 400), still on the canvas.
- **Font fallback:** if `install` forgot the rename, the build fails (`include_bytes!` of a deleted file) – good.
