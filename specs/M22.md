# M22 – Trim and extend

Branch `feature/trim-extend` (from `main`, M13–M21 merged). Crates touched: `hc-geom` (new module `trim`),
`hc-project` (one new `Project` method), `app`. No project format change (results are plain `Line` / `Arc` contours),
no new dependency.

## User decisions (override anything below)
- Two new tools, **Trim** and **Extend**: a sidebar tile each and a Draw menu entry each, **no keyboard shortcut**
  (no key in `canvas::input`, `""` as key text, sidebar rows "–" in `shortcuts.md`, `docs_shortcuts` unchanged).
- Workflow: select the limiting objects (lines, circles, arcs, any contour) with the Select tool, then pick Trim or
  Extend, then click. Trim = click the piece to cut away. Extend = click near an end of an open line/arc/polyline to
  lengthen it to the nearest limit in that direction. Repeated clicks allowed; `Esc` leaves the tool (existing rule).
- Nothing selected when the tool starts: no limits; the status bar and Properties show
  "Trim: select the limiting objects first" (resp. "Extend: …") and clicks do nothing.
- Works on segments inside contours (chained DXF). Trimming a closed contour opens it; trimming the middle of an open
  contour splits it into two items; a circle trimmed becomes an arc; Extend works only on the ends of open contours.

## Scope
**In:** `hc_geom::trim` (cut points, trim one segment piece, extend one end); `Project::split_item`; tools
`CanvasTool::Trim` / `CanvasTool::Extend` with hover preview, click, messages, Properties form, sidebar tiles, Draw
menu entries; manual tabs follow / are dropped; operations follow a split; one undo step per click; sidebar layout
change so the extra row fits (Decision 8); docs.

**Out:** trimming text specially (glyph outlines are plain contours and are trimmed like any contour, no special
code), offsets, fence / crossing / box trims, extending closed contours or middle segments, extending to the
*apparent* (extended) intersection of two limits, "trim to nothing" (deleting a whole item), a shortcut key, a
new screenshot, a new palette colour, live re-reading of the selection while the tool is active.

## Existing code this builds on (read before coding)

  segments (arcs within their sweep, full circles included, tangency = one point, no duplicates). **Reuse it**; the
  private `line_line` / `line_circle` / `circle_circle` stay private.
- `Segment::closest(p)` (distance along the segment from its start), `point_at(d)`, `length()`, `reversed()`,
  `start()/end()`; `Contour::closest(p)` → (arc length, distance); `Contour::length()`.
  Arc: `sweep > 0` CCW, `|sweep| == 2π` = full circle; `Circle::to_contour` = one Arc, `start_angle 0`, `sweep 2π`.
- M16 `fillet.rs` builds new `Contour { segments, closed }` from pieces; copy that style. `shapes::rect(min,w,h,0)` =
  Line (0,0)→(30,0), (30,0)→(30,10), (30,10)→(0,10), (0,10)→(0,0) for `rect((0,0),30,10,0)`.
- `AppState::replace_contour` (M16) remaps manual tabs by nearest point; it stays for Round corners. Trim/Extend use
  the new `apply_parts` (below) because tabs on a removed piece must be dropped.
- `commit_undo(idle)` runs every frame: one click that changes the project = one undo step. **No new undo code.**
- `set_tool`, `escape` (leaves a non-Select tool when nothing is pending; selection kept), `canvas::input` calls
  `fillet_click(w, SNAP_PX / zoom)` with the **raw** world point for Round corners; Trim/Extend do the same.
- `Project::remove_item`, `take_id` (private), `Operation.items`, `Tabs.manual: Vec<ManualTabs { item, positions }>`

## Decisions
1. **Limits are frozen ids, live geometry.** `set_tool(Trim | Extend)` copies the selection into
   `AppState::trim_limits: Vec<u64>`; every other `set_tool` clears it. Each click reads the current geometry of
   those ids (missing ids skipped, `Geom::Point` skipped, visible or hidden alike). So a limit that was itself trimmed
   cuts with its new shape, undo cannot break anything, and other UI that changes the selection mid-tool has no effect.
   When a split creates a new item from an item in `trim_limits`, the new id is appended to `trim_limits` **and**
   inserted into `selection` (the highlighted set = the limits). To change the limits: Esc, select, pick the tool again.
2. **Self-limits allowed.** All segments of every limit item count, including other segments of the item being
   trimmed/extended (select everything → trim crossings). The clicked segment itself is always excluded. Touching at a
   shared vertex is not a cut (cut points within `TRIM_TOL` of a segment's ends are ignored).
3. **Trim works per segment.** The removed piece lies inside the clicked segment: between the two cut points around
   the click, or between a segment end (vertex or contour end) and the nearest cut point. A segment with no cut point
   → "Nothing to trim here". A full circle needs ≥ 2 distinct cut points (one tangent touch → nothing).
   Consequences: closed contour → one open contour starting at the cut after the gap and ending at the cut before it;
   open contour, piece at an end → one shorter contour; open contour, piece in the middle → two contours; full circle
   → one open arc. An item is never removed entirely (impossible by construction), so there is no delete path.
4. **Split rule:** the first part (from the old start) keeps the item id; the second part becomes a new item
   (`Project::split_item`: same layer and source, inserted right after the original in `items`, and its id inserted
   right after the original's id in **every operation that lists the original**). Both pieces keep being machined by
   the same operations; nothing disappears silently. Pocket / Contour Inside/Outside ops on a now-open item show the
   existing "Needs closed contours" error, which is correct.
5. **Manual tabs** of the item (every op): each position's old point is assigned to the part within `TRIM_TOL`
   (1e-6 mm) of it (first part wins ties) and re-expressed as a fraction of that part's length; points on the removed
   piece are dropped; the second part gets its own `ManualTabs` entry (pushed to the same op) when it receives
   positions; an entry left with no positions is removed (the item goes back to automatic tabs). Extend uses the
   same function with one part (all old points lie on the longer contour).
6. **Extend** continues the end segment along its own line (a ray) or its own circle (in the arc's direction, at
   most up to the full circle) and stops at the **nearest** intersection with a limit that is more than `TRIM_TOL`
   beyond the current end. So an end that already touches a limit goes to the next one (each click = next limit).
   The end segment is lengthened in place (no extra segment): a line stays one line, `shapes::recognize` keeps working.
   Which end: `contour.closest(click).0 < contour.length() / 2` → start, else end. Only open contours; no hit →
   "No limit in that direction".
7. **Picking** uses the raw click: the nearest segment (`trim::nearest_segment`) of a visible `Geom::Contour` item
   within `SNAP_PX / zoom` (10 px); ties keep the first item in project order. Trim considers every contour, Extend only
   open ones. Hover preview: Trim draws the piece to remove in the measure colour (`CanvasPalette::measure`, solid,
   3 px) with label "Trim"; Extend draws the added piece dashed in the snap colour with label "Extend"; when the
   result is None the label is "Nothing to trim" / "No limit". No preview and no message while `trim_limits` is empty.
8. **Sidebar room:** Trim and Extend go into the Draw group after Round corners (blue, `SideAct::Tool(_)` →
   `Tint::Draw` already): the group grows from 8 to 10 tiles = one more row (+42 px). At 1280×800 with Simulation and
   Issues open the slack is only 10 px today (measured: last tile bottom 635, panels top 650). Fix: in `App::show`
   (`main.rs` ~line 151) call `panels::sidebar` **before** `panels::sim_panel` and `panels::issues` (right after
   `panels::status_bar`). The sidebar then runs from the messages panel down to the status bar, and the Simulation and
   Issues panels start right of the sidebar (≈ 112 px narrower). Expected: last tile bottom ≈ 677, status top ≈ 776,
   ~94 px slack at 1280×800 with everything open (even 1280×720 fits). Tile size stays 36 px. **Question for the
   user** (visible layout change) – see the end.
9. **Icons** (Phosphor Fill 2.1.2, verified in `style.css` and in the bundled TTF cmap):
   Trim = `scissors` U+EAE0, Extend = `arrow-line-right` U+E064.
10. **Messages:** Warning "Nothing to trim here" / "No limit in that direction" when a picked segment gives no
    result; no message on success, on a miss (no segment within tol) or with no limits.

### `crates/hc-geom/src/trim.rs` (new) and `lib.rs`

segments (M22).`

```rust
use crate::{Contour, Point, Segment, EPS};
use std::f64::consts::TAU;

/// Cut points closer than this (mm, along the segment) to each other or to a segment end are merged / ignored.
pub const TRIM_TOL: f64 = 1e-6;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum End {
    Start,
    End,
}

#[derive(Debug, Clone, PartialEq)]
pub struct Trimmed {
    /// What remains, 1 or 2 open contours; parts[0] is the one that keeps the item id.
    pub parts: Vec<Contour>,
    /// The removed piece (one segment), for the preview.
    pub removed: Segment,
}

/// (segment index, distance along that segment, distance from p) of the segment nearest to `p`; first wins ties.
/// None for an empty contour.
pub fn nearest_segment(c: &Contour, p: Point) -> Option<(usize, f64, f64)>;

/// Distances along `seg` (from its start) where it meets `limits` (`Segment::intersections`, d = `seg.closest(q)`),
/// ascending, merged within TRIM_TOL. Partial segment: only d in (TRIM_TOL, len - TRIM_TOL). Full circle
/// (`|sweep| >= TAU - EPS`): d in [0, len), a d >= len - TRIM_TOL counts as 0, and the last value is dropped when
/// within TRIM_TOL of `first + len`.
pub fn cuts(seg: &Segment, limits: &[Segment]) -> Vec<f64>;

/// Removes the piece of segment `seg` around distance `d` (Decision 3). None = nothing to trim.
pub fn trim(c: &Contour, seg: usize, d: f64, limits: &[Segment]) -> Option<Trimmed>;

/// Lengthens the start or end segment of an open contour to the nearest limit (Decision 6).
/// Some((new contour, added piece)); None when closed, empty, no limits or no hit.
pub fn extend(c: &Contour, end: End, limits: &[Segment]) -> Option<(Contour, Segment)>;
```

Private helper `fn sub(s: &Segment, from: f64, to: f64) -> Segment` (from < to, arcs may use from < 0 or
to > len for the circle wrap):
- Line: `Line { start: if from <= 0.0 { start } else { s.point_at(from) }, end: if to >= len { end } else {
  s.point_at(to) } }` (exact end points keep joints bit-identical).
- Arc: `sg = sweep.signum()`; `Arc { center, radius, start_angle: start_angle + sg * from / radius, sweep: sg * (to -
  from) / radius }`.

`trim(c, seg, d, limits)`:
1. `s = c.segments.get(seg)?`, `len = s.length()`, `cs = cuts(s, limits)`.
2. **Full circle** (`c.segments.len() == 1` and `|sweep| >= TAU - EPS`): `cs.len() < 2` → None.
   `hi = first cut > d, else cs[0] + len`; `lo = last cut <= d, else cs.last() - len`.
   `removed = sub(s, lo, hi)`, kept = `sub(s, hi, lo + len)`; `parts = vec![Contour { segments: vec![kept], closed:
   false }]`.
3. Otherwise `cs.is_empty()` → None. `lo = last cut < d, else 0.0`; `hi = first cut >= d, else len`.
   `removed = sub(s, lo, hi)`; `before = (lo > 0.0).then(|| sub(s, 0.0, lo))`; `after = (hi < len).then(|| sub(s,
   hi, len))`.
   `a = segments[..seg] + before`, `b = after + segments[seg + 1..]`.
   - closed: `parts = vec![Contour { segments: b + a, closed: false }]`.
   - open: `parts` = `a`, `b` as open contours, empty ones skipped (1 or 2 parts, `a` first).

`extend(c, end, limits)`:
1. None when `c.closed`, `c.segments.is_empty()` or `limits.is_empty()`.
2. Outward segment `o`: `End::End` → last segment; `End::Start` → `first.reversed()` (its end is the contour start).
3. Probe `q`:
   - Line `o` (a→b, `len >= EPS`, else None): `u = (b - a) * (1/len)`; `big` = 1.0 + length of the diagonal of the
     bbox of all limit segments and `b`; `q = Line { start: b, end: b + u * big }`.
   - Arc `o`: `rest = TAU - |sweep|`; `rest < TRIM_TOL / radius` → None;
     `q = Arc { center, radius, start_angle: start_angle + sweep, sweep: sweep.signum() * rest }`.
4. `hit = min over limits of q.closest(p) for p in q.intersections(limit)`, keeping only values `> TRIM_TOL`; none →
   None.
5. `added = sub(&q, 0.0, hit)`. New segment, `sg = sweep.signum()`, `k = hit / radius` for arcs:
   - End, Line: `Line { start, end: added.end() }`; End, Arc: `sweep + sg * k`.
   - Start, Line: `Line { start: added.end(), end }`; Start, Arc (on the original first segment's own `sg`):
     `start_angle - sg * k`, `sweep + sg * k`.
   Return the contour with that segment replaced (`closed: false`) and `added`.

## Risks
- Per-segment trimming: a DXF circle made of two half arcs (or a polyline whose piece spans a vertex) needs one click
  per segment; the piece stops at the joint. Matches the requested "part of a segment"; documented as "corner/end".
- Intersections from `Segment::intersections` use EPS 1e-9; a limit that only almost touches (gap > 1e-9) does not
  cut. DXF parts chained with 0.01 mm gaps can therefore miss a limit drawn exactly to the gap.
- Line-probe length from the limits' bbox: limits are finite, so a hit always lies inside it; no fixed "infinite"
  constant.
- Moving the sidebar before the bottom panels changes every screenshot and narrows the Simulation/Issues panels by
  the sidebar width; tests that compare y positions with the Issues panel must use the status bar.
- Tab remap by 1e-6 distance: tabs very close to a cut stay on the remaining part (fine).
