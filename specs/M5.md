# M5 – Toolpaths (`hc-toolpath`) + toolpath display

## Scope
**In:** new crate `crates/hc-toolpath`: Engrave, Contour (Inside/Outside/On, Climb/Conventional), Pocket (concentric rings, islands), Drill (plain/peck);
depth passes, straight plunge entry, safe/clearance Z rules, feature ordering, per-op errors. App: automatic regeneration, toolpath drawing with a
show/hide toggle, per-op error in the operations list, auto-fit stock on DXF import (M4 ruling f). `Contour::as_circle` in hc-geom.
**Out:** tabs (M6, only the hook below), G-code (M7), sanity checks/warnings (M8), simulation (M9), ramp/helix entry, linked pocket rings,
rest machining, adaptive clearing, lead-in/out, grouping ops by tool, tool-shape awareness (V-bit/ball are treated as cylinders of `diameter`).

## Dependencies
`hc-toolpath`: `hc-geom`, `hc-project` (path), `cavalier_contours = "0.9"` (0.9.0, MIT OR Apache-2.0, pure Rust, no default features,
deps `static_aabb2d_index`/`num-traits` are MIT/Apache; MSRV 1.88, we have 1.99). It offsets polylines **with bulges** (arcs stay arcs) and offsets
a `Shape` (CCW boundaries + CW holes) together, which is exactly concentric pocketing with islands. Suitable, no alternative needed.
App: `hc-toolpath` (path).

## Conventions
All values mm, mm/min. Z0 = stock top, cutting Z negative. Machine: `safe_z` (between features, op start/end), `clearance_z` (rapid-down level
before a plunge, drill R plane). Spindle is M3 (CW seen from above).

## Public API (`hc-toolpath/src/lib.rs`)
```rust
#[derive(Debug, Clone, Copy, PartialEq)] pub struct Point3 { pub x: f64, pub y: f64, pub z: f64 }

#[derive(Debug, Clone, PartialEq)]
pub enum Move {
    Rapid(Point3),                                                    // G0; changes Z only or XY only, never both
    Linear { to: Point3, feed: f64 },                                 // G1
    Arc { to: Point3, center: Point, ccw: bool, feed: f64 },          // G2/G3 in XY, to.z == current z, |sweep| <= π
    Drill { at: Point, z_bottom: f64, peck: Option<f64>, r_plane: f64, feed: f64 }, // G81/G83, G98: returns to the Z it started at
}

#[derive(Debug, Clone, PartialEq)]
pub struct Toolpath { pub op_id: u64, pub tool_id: u32, pub rpm: u32, pub moves: Vec<Move> }

#[derive(Debug, Clone, PartialEq)]
pub enum ToolpathError {
    MissingTool(u32), MissingItem(u64), NoItems,
    InvalidParam(&'static str),   // field name, e.g. "depth_per_pass"
    OpenContour(u64),             // Pocket / Contour Inside|Outside on an open contour
    UnsupportedItem(u64),         // a Point in Engrave/Contour/Pocket, a non-circle contour in Drill
    OffsetVanished(u64),          // tool too large for this item (inside contour / pocket boundary)
}
impl std::fmt::Display for ToolpathError {} // e.g. "Tool too large for item 17", "Needs closed contours (item 4 is open)"
impl std::error::Error for ToolpathError {}

/// Enabled ops in user order (disabled skipped), one entry per op.
pub fn generate(project: &Project) -> Vec<(u64, Result<Toolpath, ToolpathError>)>;
pub fn generate_op(project: &Project, op: &Operation) -> Result<Toolpath, ToolpathError>;

/// Pass Z values, see "Depth passes".
pub fn depth_levels(depth: f64, depth_per_pass: f64) -> Vec<f64>;
/// Closed-contour offset. dist > 0 grows, < 0 shrinks, independent of input orientation. Results are CCW. Empty = vanished.
pub fn offset_closed(c: &Contour, dist: f64) -> Vec<Contour>;
/// Pocket rings per offset level, outermost level first. Boundaries CCW, island rings CW.
pub fn pocket_rings(boundary: &Contour, islands: &[Contour], radius: f64, step: f64) -> Vec<Vec<Contour>>;
```
`hc-geom`: `impl Contour { pub fn as_circle(&self) -> Option<Circle> }` (one arc with |sweep| = 2π within 1e-9). The app's `circle_diameter`
is replaced by it (delete the duplicate).

Modules: `lib.rs` (types, `generate*`, validation, ordering, move emission), `offset.rs` (cavalier conversion, `offset_closed`, `pocket_rings`).
`Point3`/`Move` derive no serde (not saved).

## Cavalier conversion (`offset.rs`, private)
- `split_large_arcs(&Contour) -> Contour`: every arc with |sweep| > π becomes two equal halves. Used before conversion **and** before move
  emission, so |bulge| ≤ 1, full circles become 2 vertices, and no `Move::Arc` is a full circle (no from == to ambiguity for M7/M9).
- Contour → `Polyline<f64>`: per segment push `(start.x, start.y, bulge)`, line bulge 0, arc bulge `tan(sweep/4)`. Open: also push the end
  vertex with bulge 0. `set_is_closed(c.closed)`.
- Polyline → Contour: `Contour::from_bulge_vertices(&[(Point, bulge)], pl.is_closed())`.
- Cavalier sign: positive offset = to the **left** of travel (inward for CCW). So `offset_closed(c, d)` orients a copy CCW and calls
  `parallel_offset(-d)`; results with |area| < 1e-6 are dropped. Pocket: `Shape::from_plines([boundary CCW, islands CW])`, then
  `shape.parallel_offset(radius)`, then repeatedly `parallel_offset(step)` until the shape is empty; each level = its ccw + cw plines.
  Cap 10 000 levels (`InvalidParam("stepover_pct")` beyond).

## Direction rule (M3 spindle) – derivation
Tool rotates CW seen from above. Travel +X: the tooth on the −Y side moves −X relative to the tool centre, i.e. the same way the workpiece moves
relative to the tool → down (climb) milling when the material is on −Y = the **right** of travel. So: **Climb ⇔ material on the right of travel.**
| cut | Climb | Conventional |
|---|---|---|
| Outside (part inside the path) | CW | CCW |
| Inside (hole) | CCW | CW |
| On, closed | CW (treated as Outside) | CCW |
| On, open | drawing direction | reversed |
| Pocket (always climb; no direction field) | boundary rings CCW, island rings CW (cavalier's natural orientation) | – |
| Engrave | drawing direction (closed: as stored) | – |
Applied after offsetting via `Contour::set_orientation`, so it is independent of the input orientation.

## Operations → features
Features of one op = its items (missing id → `MissingItem`, empty → `NoItems`).
- **Engrave:** each contour as is, centre on the line. Point → `UnsupportedItem`.
- **Contour:** Outside → `offset_closed(c, +r)`, Inside → `offset_closed(c, −r)` (empty → `OffsetVanished(id)`; several loops, e.g. a
  dumbbell, are all cut as one feature), On → no offset. Inside/Outside on an open contour → `OpenContour`. r = tool.diameter / 2.
- **Pocket:** all closed contours of the op → `containment_tree` over **only the op's items**: even depth = boundary, odd depth = island of its
  parent (a selected contour inside a selected contour is an island automatically; unselected contours are ignored). Each boundary + its
  islands = one feature → `pocket_rings(b, islands, r, stepover_pct/100 · D)`; no rings → `OffsetVanished(boundary id)`. Open → `OpenContour`.
  Within each depth pass the rings are cut **innermost level first** (plunge in the middle, the wall ring last). Between rings: retract to
  clearance_z, rapid XY, plunge (shortcut: no linking at depth; upgrade with M6/M9 if air time annoys, links must not cross islands).
- **Drill:** circle (`as_circle`) → its centre, `Point` → itself; any other contour → `UnsupportedItem`. Each → `Drill { at, z_bottom: −depth,
  peck, r_plane: clearance_z, feed: op.plunge_feed }`. `depth_per_pass` and `feed` are ignored. Hole Ø vs tool Ø is M8.
- **Tabs hook (M6):** all contour/pocket cutting at one Z goes through one private fn `cut_pass(out: &mut Vec<Move>, path: &Contour, z: f64,
  feed: f64)`. M6 replaces its body (lift over tabs when z < −depth + tab height). `op.tabs` is ignored in M5.

## Depth passes and Z rules
- `depth_levels(depth, dpp)`: n = ceil(depth/dpp − 1e-9), **equal steps** z_i = −depth·i/n, i = 1..n. (5, 2) → [−5/3, −10/3, −5]; (6, 2) →
  [−2, −4, −6]; (1, 2) → [−1]. Every pass ≤ dpp, no thin last pass.
- Per feature: `Rapid(start XY @ safe_z)` (from the previous end: first `Rapid` up to safe_z, then XY), `Rapid(start @ clearance_z)`, then per
  level: `Linear(start @ z_i, plunge_feed)` and the cut at `feed`.
  - Closed path: loop it once per level, plunge again at the start (no retract between levels).
  - Open path: reverse direction every level (zig-zag), plunging at the current end (no retract, no air moves).
  - Re-entry rule (all kinds): if the tool is already at the next path's start, plunge in place; otherwise `Rapid` up to clearance_z,
    XY rapid, plunge. Pocket: so every ring after the first of a level re-enters from clearance, and so does the first (innermost) ring of
    each new level, since the previous level ended on the wall ring.
- After a feature: `Rapid` up to safe_z. A toolpath starts with `Rapid(first start XY @ safe_z)` (M7 has already sent G0 Z safe in the tool
  change block) and ends at safe_z.
- Drill: `Rapid(at @ safe_z)`, `Drill` (returns to safe_z).
- Validation (before anything else, → `InvalidParam`): non-finite anything; depth ≤ 0; dpp ≤ 0 or depth/dpp > 10 000 (non-drill); feed ≤ 0
  (non-drill); plunge_feed ≤ 0; tool.diameter ≤ 0 (Contour/Pocket); stepover_pct ∉ (0, 100]; peck ≤ 0; clearance_z ≤ 0; safe_z < clearance_z.
  Missing tool → `MissingTool`. rpm 0 is M8's business.

## Ordering
- **Ops:** strict user order (tool changes are manual and cheap to reorder in the list; M8 may warn about repeated tool changes). PLAN.md updated.
- **Features within an op:** containment depth among the op's own closed contours, **deepest first** (holes and inner parts are cut before
  the outer contour that frees the part), then nearest neighbour from the previous feature's end (first from (0,0)) by distance to the
  feature start. Open contours are not flipped to the nearer end (shortcut). Drill: nearest neighbour only.

## App
- `AppState`: `toolpaths: Vec<(u64, Result<Toolpath, ToolpathError>)>`, `toolpaths_for: Option<Project>`, `show_toolpaths: bool` (default
  true, not saved). `refresh_toolpaths(&mut self)` runs at the top of `App::show`: if `toolpaths_for != Some(project)`, regenerate and store a
  clone. **Automatic**, no Generate button; comparing the project avoids missed invalidations (cheap at hobby sizes).
- Canvas (after items, before selection highlight): feed moves (Linear with XY change, Arc via `tessellate_arc`) solid 1.5 px in a toolpath
  colour (blue-ish, theme-aware); XY rapids dashed thin grey; Drill = circle of tool Ø plus a cross. Z is not shown (top view; Z = M9).
  Vertical moves are invisible. Ops with errors draw nothing.
- View menu: checkbox "Show toolpaths".
- Operations list: an op whose result is `Err` gets a second line in the error colour: `Error: <Display>`. Toolpath errors do not go to
  the message panel.
- **Auto-fit stock** in `import_dxf`: if `project.stock == Project::new().stock` and `operations.is_empty()` and the items bbox has width > 0
  and height > 0 → stock min = bbox.min, width/height = bbox size, thickness and origin unchanged.

## Risks
- Cavalier on imperfect DXF contours (self-touching, gaps closed by chaining tolerance, near-zero segments): may return odd loops. We do not
  set `handle_self_intersects`; M8 will flag `OffsetVanished`. Keep test 14 as the real-data guard.
- Concentric rings with stepover > 50 % can leave an uncut island in the middle or in corners. Not fixed here; M8 should warn.
- Regenerating on every project change runs while dragging a DragValue; a large fine pocket (e.g. 400×200 mm, Ø2, 10 %) may lag. Upgrade
  path: per-op cache keyed by the op + its items + tool.
- Straight plunge into material with end mills that cannot centre-cut is the user's risk until ramp entry exists.
- Equal-step depth levels differ from "full dpp, remainder last"; the UI value is a maximum per pass. Document in M11.
