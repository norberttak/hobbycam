# M16 – Round corners (fillet)

Branch `feature/round-corners` (from `main`, M13–M15 merged). Crates touched: `hc-geom` (new module `fillet`), `app`.
No project format change (a fillet only rewrites `Item::geom` with the existing `Line` / `Arc` segments), no new
dependency.

## User decisions (override anything below)
- Works on drawn **and** imported DXF geometry.
- The user sets the radius, then either clicks single sharp corners on the canvas, or applies it to the selected
  contours to round every sharp corner.
- Corners where the radius does not fit are skipped and reported (message with the count).
- Undoable.
- Only corners between two straight lines are rounded; line–arc / arc–arc corners are skipped and reported (confirmed).
- **No keyboard shortcut** for Round corners (overrides every `N` below): no `Key::N` in `canvas::input`, the Draw menu
  entry and the sidebar button pass `""` as the key text, no shortcuts.md keyboard row (sidebar row without a key),
  `docs_shortcuts` unchanged, CHANGELOG line without "(`N`)", test K1 selects the tool by clicking the sidebar button
  instead of pressing `N`, and a test asserts that pressing `N` over the canvas leaves the tool unchanged.

## Scope
**In:**
- `hc_geom::fillet`: round the joint between two **straight lines** of one contour with a tangent arc of radius `r`;
  single joint or every sharp joint of a contour; radius-fit check; skip reasons.
- New canvas tool **Round corners** (`CanvasTool::Fillet`): sidebar button, Draw menu entry, key `N`, Properties form
  with **Radius** and a **Round all corners of selection** button, hover highlight + dashed preview arc on the canvas,
  messages for skipped corners.
- Manual tab positions of a rounded item are moved to the nearest point of the new contour.
- Docs: `drawing.md`, `shortcuts.md`, `CHANGELOG.md`.

**Out (explicitly):** chamfers; variable radius / different radius per corner in one press; fillets at line–arc or
arc–arc joints (reported as skipped, see Decisions); a fillet between two separate contours / items (trim-extend);
the ends of open contours; "un-round" (Undo does that); recognising slots or partially rounded rectangles in
Properties; a new screenshot; a numeric "corner X/Y" field; selecting items while the tool is active.

## Existing code this builds on (read before coding)
- `Contour { segments, closed }`: segment `i` ends where `i+1` starts; in a closed contour the last ends at
  `segments[0].start()`. Arc `sweep > 0` = CCW. `shapes::rect(min, w, h, r)` builds Line, Arc, Line, Arc, … starting at
  `(min.x + r, min.y)`, CCW; edges shorter than `EPS` are omitted.
- `shapes::recognize` (M15) recognises an 8-segment closed contour (alternating line/arc, equal radii, quarter arcs
  with the area's sign) as `Primitive::Rect { r }`. A fully filleted sharp rectangle must therefore come out as
  exactly that layout (acceptance test G1/S3).
- `AppState::commit_undo(idle)` runs every frame in `App::show`: a click or a button press that changes the project is
  one undo step. **No new undo code.**
- `AppState::canvas_click` is called from `canvas::input` with a snapped point for every non-Select tool; `escape()`
  leaves a non-Select tool; `CanvasTool::hint` gives the status bar text; `panels::right` shows `draw_form` for every
  tool except Select / SetOrigin.
- Manual tabs (`ManualTabs { item, positions }`) are fractions of the contour length from its start
  (`tab_at` uses `t.rem_euclid(1.0) * len`). Ops reference items by id; toolpaths regenerate via the whole-project
  compare in `refresh_toolpaths`.
- The snap engine (`snap::candidates`) emits `SnapKind::Corner` for every segment start, but without the joint index
  and mixed with midpoints / centres / intersections that would pull the click off the corner. **Do not use it to
  find the clicked corner**; use `fillet::joints` (below). Only `snap::marker(…, SnapKind::Corner, …)` is reused for
  drawing the highlight.

## Decisions
1. **Line–line only.** A sharp joint where either side is an arc is skipped with reason "not between two straight
   lines". DXF LWPOLYLINEs without bulges, chained LINEs and the drawn line/rectangle tools produce lines only, which
   covers the usual hobby parts; bulge arcs in polylines are mostly tangent (slots, rounded corners) and are then not
   corners at all. Line–arc formulas need sign cases per arc side; not worth it for M16.
2. **Sharp** = the turn angle `|θ|` between the incoming and outgoing tangent directions at the joint is greater than
   `FILLET_MIN_TURN` = 1° (`1.0_f64.to_radians()`). Joints at or below it (tangent joints of rounded rectangles and
   slots, flattened spline/ellipse vertices below 1°) are not corners: silently ignored by "round all", and a click
   reports "Not a sharp corner". Arc tangents are used for this test so tangent line–arc joints stay silent.
3. **Fit** uses the current geometry: the tangent distance `t = r·tan(|θ|/2)` must be ≤ the still unused length of
   each adjacent line + `FILLET_FIT_TOL` (1e-6 mm). "Round all" works greedily in joint order (closed: 0, 1, …, n−1;
   open: 1, …, n−1); a fillet uses up `t` at the end of the previous line and at the start of the next one, so a later
   joint sees the shortened line. A line may be used up **completely**: when its leftover length is below
   `FILLET_FIT_TOL` it is dropped (same as `shapes::rect` with r = h/2 giving a slot).
4. **Open contours:** the two end points are not corners (joints 1..n−1 only). **Closed:** joint 0 is the vertex at
   `segments[0].start()`; its arc is appended as the **last** segment, so the result starts at the trimmed start of
   segment 0 (exactly like `shapes::rect`). Sweep = signed turn angle, so orientation stays consistent (convex corners
   of a CCW contour get CCW arcs, concave ones CW).
5. **Manual tabs are remapped by nearest point**, not kept as fractions: rounding joint 0 moves the contour start by
   `t` and every fillet shortens the length, so kept fractions would slide every tab along the part. Remapping
   (`new.closest(old point).0 / new length`) keeps each tab where the user put it (a tab on the cut-off corner lands on
   the arc). It is a few lines and needs no special cases. Automatic tabs are recomputed anyway.
6. **Hover/click pick:** the nearest joint (sharp or not) of any visible contour item within the snap radius
   (`SNAP_PX / zoom`, 10 px); ties keep the first item in project order. The click uses the **raw** cursor point,
   not the snapped one.
7. **Shortcut `N`** (free; L R C T O F, Space, Del are taken). Icon: Phosphor `bezier-curve` U+EB00.
8. Radius default **2 mm**, its own `DrawForm` field (`fillet_r`); the rectangle's `r` (default 0) is not reused.

```rust
use crate::{Contour, Point, Segment, EPS};

/// Joints turning by this angle or less are not corners (radians, = 1°).
pub const FILLET_MIN_TURN: f64 = 0.017453292519943295;
/// Fit tolerance (mm); a line shortened below this is dropped.
pub const FILLET_FIT_TOL: f64 = 1e-6;

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum FilletSkip {
    /// r is not finite or r < EPS.
    BadRadius,
    /// No such joint, a tangent / almost straight joint (|θ| <= FILLET_MIN_TURN) or a zero-length side.
    NotSharp,
    /// Sharp, but one side is an arc.
    NotLines,
    /// The tangent distance does not fit; `max_r` is the largest radius that would.
    TooLarge { max_r: f64 },
}

#[derive(Debug, Clone, PartialEq)]
pub struct FilletAll {
    pub contour: Contour,
    pub rounded: usize,
    pub not_lines: usize,
    pub too_large: usize,
}

/// Every joint (index, vertex): closed 0..n, open 1..n (joint k is between segment k-1 (mod n) and k, at
/// segments[k].start()). Contours with fewer than 2 segments have none.
pub fn joints(c: &Contour) -> Vec<(usize, Point)>;

/// Rounds joint `joint` with radius `r` using the full current lengths of its two lines.
/// Ok = (new contour, the new arc). Err leaves nothing changed.
pub fn fillet_corner(c: &Contour, joint: usize, r: f64) -> Result<(Contour, Segment), FilletSkip>;

/// Rounds every sharp joint greedily in joint order (Decision 3). NotSharp joints are not counted.
/// BadRadius: the input unchanged, all counts 0.
pub fn fillet_all(c: &Contour, r: f64) -> FilletAll;
```

**Private helpers** (same file):
- `fn start_dir(s: &Segment) -> Option<Point>` / `fn end_dir(s: &Segment) -> Option<Point>`: unit tangent in travel
  direction. Line: `(end − start) / len`, `None` when `len < EPS`. Arc at angle `a` (start: `start_angle`, end:
  `start_angle + sweep`): `Point::new(-a.sin(), a.cos()) * sweep.signum()`.
- `fn turn(prev: &Segment, next: &Segment) -> Option<f64>`: `u1 = end_dir(prev)?`, `u2 = start_dir(next)?`,
  `θ = u1.cross(u2).atan2(u1.dot(u2))` (in (−π, π], > 0 = left turn).
- `fn corner_arc(v: Point, u1: Point, u2: Point, theta: f64, r: f64) -> (f64, Point, Point, Segment)` returning
  `(t, t1, t2, arc)`:
  - `t = r * (theta.abs() / 2.0).tan()`
  - `t1 = v - u1 * t`, `t2 = v + u2 * t`
  - `n = if theta > 0.0 { Point::new(-u1.y, u1.x) } else { Point::new(u1.y, -u1.x) }` (left / right normal of u1)
  - `center = t1 + n * r`; `start_angle = (t1.y - center.y).atan2(t1.x - center.x)`; `sweep = theta`
  - `arc = Segment::Arc { center, radius: r, start_angle, sweep }`

**Shared core** `fn fillet_joints(c: &Contour, which: &[usize], r: f64) -> (Contour, Vec<Result<Segment, FilletSkip>>)`
(one result per entry of `which`, in that order; `which` must be ascending and only contain indices from `joints(c)`;
any other index → `Err(NotSharp)`):
1. If `!(r.is_finite() && r >= EPS)`: return `(c.clone(), vec![Err(BadRadius); which.len()])`.
2. `n = c.segments.len()`; `cs = vec![0.0; n]`, `ce = vec![0.0; n]` (length used at each line's start / end);
   `arc_at: Vec<Option<(Point, Point, Segment)>> = vec![None; n]` indexed by joint (t1, t2, arc).
3. For each `k` in `which`: `prev = (k + n - 1) % n`, `next = k`, `v = c.segments[k].start()`.
   - `θ = turn(prev, next)`; `None` or `|θ| <= FILLET_MIN_TURN` → `Err(NotSharp)`.
   - either segment not a `Line` → `Err(NotLines)`.
   - `avail_p = len(prev) − cs[prev] − ce[prev]`, `avail_n = len(next) − cs[next] − ce[next]`;
     `t = r·tan(|θ|/2)`; if `!t.is_finite() || t > avail_p + FILLET_FIT_TOL || t > avail_n + FILLET_FIT_TOL` →
     `Err(TooLarge { max_r: avail_p.min(avail_n).max(0.0) / (|θ|/2).tan() })`.
   - else `(t, t1, t2, arc) = corner_arc(v, u1, u2, θ, r)`; `ce[prev] = t`, `cs[next] = t`;
     `arc_at[k] = Some((t1, t2, arc))`; `Ok(arc)`.
4. Build: for `i` in `0..n`:
   - segment `i`: an `Arc` is pushed unchanged. A `Line { start, end }` becomes `Line { start: arc_at[i].t2 or start,
     end: arc_at[(i+1) % n].t1 or end }` (the joint `(i+1) % n` only exists when `closed || i + 1 < n`), pushed only
     when `len − cs[i] − ce[i] >= FILLET_FIT_TOL`.
   - then, when `closed || i + 1 < n`, push `arc_at[(i+1) % n].arc` if present.
5. Result `Contour { segments, closed: c.closed }`.

`fillet_corner(c, k, r)`: `k` not in `joints(c)` → `Err(NotSharp)`; else `fillet_joints(c, &[k], r)` and map
`Ok(arc)` → `Ok((contour, arc))`. `fillet_all(c, r)`: `fillet_joints(c, &all joint indices, r)`, count `Ok` →
`rounded`, `NotLines` → `not_lines`, `TooLarge` → `too_large`; on `BadRadius` return input unchanged, counts 0.

## Risks
- Greedy order makes "round all" on a short side asymmetric (G7): documented by the skip message; the user can
  undo and pick a smaller radius.
- Imported contours whose joints differ by up to the chain tolerance (0.01 mm): the vertex is taken as
  `segments[k].start()`, so a trimmed previous line may end up to 0.01 mm off its original line. Harmless for milling.
- Flattened splines/ellipses with > 1° per vertex get many tiny arcs on "round all" (more segments, same shape).
- Two items sharing a corner (touching parts): the click rounds the first in project order only.
- `atan2` at ±π for arc start angles: tests compare points, not raw angles.
