# M20 – Move by key points, snap to objects and grid

Branch `feature/move-snap`, created on top of `feature/measure-tool` (M19, not merged yet). Version 0.3.0.
Crates touched: `app`, `hc-project` (new `prefs.rs`). **No project format change**, nothing in G-code, no new
dependency (`serde`/`serde_json`/`directories` are already in `hc-project`).

## User decisions (override anything below)
1. A drag grabs the **key point nearest to the pointer** of the items that will move (circle centre, line end or
   midpoint, corner, arc centre, intersection, DXF point), not only within the snap radius. With the Select tool a
   marker shows that point while the pointer is over a movable item, before the button is pressed.
2. Grid snapping uses the visible **minor grid** (`view::grid_step(zoom, units, 15.0)`, as drawn in `canvas.rs`).
   No grid size setting.
3. Two checkboxes in the Settings window, **Snap to objects** and **Snap to grid**. They apply wherever snapping is
   used: moving, Line/Rect/Circle/Text placement, Measure, Set origin. **Round corners** keeps using the raw clicked
   point (its corner pick is not a snap); the docs say so.
4. The two options are an **app preference of this computer** in `prefs.json` next to `tools.json`; missing or broken
   file → both on. The project format does not change. It must also work in the App Store (`appstore`) build.

## Scope
**In:** grab-point rule and hover marker; drop target order object → grid → free; `SnapKind::Grid`; pure
`snap::grid_snap`; one shared snap rule for move, drawing tools, Measure and Set origin; `hc_project::Prefs` with
load/save; Settings "Snapping" section; docs; `settings.png` (and the other docs pictures) regenerated.

**Out (explicitly):** a grid size or snap-radius setting; per-kind snap toggles (ends only, centres only…); snapping
of tab markers or the Round-corners pick; snapping in the Properties number fields / Transform box; a keyboard
toggle for snapping (e.g. F9); showing the grab and target marker at the same time; grid relative to the work
origin; rotate/scale by key points; copy-move; any other preference in `prefs.json`; prefs per project.

## Existing code this builds on (read before coding)
- `state.rs` `start_move(p, pick_tol, snap_r)` → grab = `snap::nearest` over the selection within `snap_r`, else
  the pressed point. `drag_move(cursor, snap_r, axis_lock)` → target = `snap::nearest` over visible, non-moving items
  within `snap_r`, else the cursor; `d = target − grab`; Shift zeroes the smaller component of `d`.
  `MoveDrag { orig, grab, delta, snap, was_dirty }`.
- `snap.rs`: `SnapKind` (declaration order = tie order), `nearest(cache, items, filter, p, radius)` (an
  Intersection needs **both** its items to pass the filter), `marker()`, `SNAP_PX = 10`.
- `state.rs` `snap_at(p, radius)` = object snap over visible items (used by `canvas.rs` tool clicks/overlay,
  `measure_live`, and many tests). `canvas_click(p, snapped)`: Set origin only acts when `snapped`.
- `canvas.rs` `input`: non-Select tools snap the click with `snap_at` (Fillet calls `fillet_click` with the raw
  point); Select: `drag_started_by` → tab marker wins, then `!shift && start_move(...)`, else a box.
  `paint` draws the grid lines at `i as f64 * step` in **drawing (world) coordinates** from world (0,0),
  `step = grid_step(v.zoom, s.project.units, 15.0)`; the drop marker comes from `s.moving.snap`.
- Tool library path: `hc_project::default_library_path()` = `directories::ProjectDirs::from("", "", "HobbyCAM")
  .config_dir()/tools.json`; `AppState::new(library_path)` loads it; tests pass `None` or a scratch path.
  Under the App Store sandbox `$HOME` is the container, so this resolves to
  `~/Library/Containers/io.github.norberttak.hobbycam/Data/Library/Application Support/HobbyCAM/` (documented in
  `install.md`), which is writable; `atomic_write` works there (the library already uses it). **No sandbox-specific
  code and no entitlement change are needed.**

## Decisions
1. **Grab point.** The items that will move: if the item under the pointer (`hit::pick_prefer`, preferring selected)
   is selected → the whole selection; else that item alone (what the plain-click rule will select); if it is a
   contour of the current tab op and not selected → no move (as today, `click_select` keeps the op). Grab =
   `snap::nearest(cands, items, |i| moving.contains(i.id), p, f64::INFINITY)` — the snap candidates of the moving
   items, unlimited radius. An Intersection counts only when both of its items move. Exact ties (within `EPS`) take
   the kind order End, Corner, Point, Center, Intersection, Midpoint, then cache order. No candidate at all → the
   pressed point. The grab rule does **not** depend on the preferences.
2. **The item jumps.** On the first drag motion the grabbed key point goes to the (snapped) pointer, so an item
   pressed far from its key point jumps once; the hover marker shows that point in advance. Intended.
3. **Drop target (one rule everywhere).** (a) "Snap to objects" on and an object candidate within
   `SNAP_PX / zoom` (moving items excluded during a move) → that point; else (b) "Snap to grid" on → the nearest
   minor-grid node; else (c) the raw pointer. Object always beats grid when in range.
4. **Shift (axis lock)** is applied after (3): `d = target − grab`, the smaller |component| becomes 0 (tie keeps X,
   as today). With grid on the grabbed point therefore stops on grid **lines** along the locked direction; the other
   coordinate stays where it was (may be off-grid).
5. **Grid snap** rounds in **drawing coordinates** (world mm, origin = drawing 0,0, where the canvas draws the lines),
   not work coordinates: `x' = (x / step).round() * step` (half away from zero, `f64::round`), same for y. This is
   bit-identical to the drawn line positions `i as f64 * step`. `step` comes from one function
   `AppState::grid_step()` used by both the painter and the snapping.
6. **Snap result for the grid:** `Snap { p, kind: SnapKind::Grid, item: 0 }` (item ids start at 1; 0 = no item).
   Marker: a 1 px "+" (arms 4 px); label **"Grid"**; same `pal.snap` colour as the other markers.
7. **Set origin** acts on any point the rule returns (object or grid). With **both** options off it takes the raw
   clicked point (otherwise it could never pick). With only grid off it needs an object snap, as today.
8. **Hover marker (Select tool):** `snap::marker` of the grab point's kind plus its kind label (`snap_label`, e.g.
   "Center"), `pal.snap`. Shown only when: tool Select, no move in progress, no box drag, no tab drag, no mouse button
   down, Shift and Space not held, the pointer is on the canvas, no tab marker under the pointer (`tab_at` → tab wins),
   and `grab_at` returns Some. During a move only the drop marker is shown (unchanged).
9. **Preferences** are app state, not project state: toggling is never an undo step and never sets `dirty`.
   `prefs.json` lives in the folder of `tools.json` (path derived from `library_path`, so tests with `None` never
   touch the disk). Missing → defaults silently; unreadable / invalid / newer version → defaults + a **Warning**
   message; a failed save → Warning, the new value stays in memory. Saved at once on each change (only when the
   value actually changes).

## Changes (exact)

### `crates/hc-project/src/prefs.rs` (new) + `lib.rs`
```rust
use crate::io::{atomic_write, from_versioned_json, no_migrate, to_checked_json};
use crate::ProjectError;
use serde::{Deserialize, Serialize};
use std::path::Path;

/// Current `prefs.json` format version.
pub const PREFS_FORMAT_VERSION: u32 = 1;

/// App preferences of this computer (not part of a project).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(default)]
pub struct Prefs {
    pub format_version: u32,
    /// Snap to object key points (ends, corners, centres, …).
    pub snap_objects: bool,
    /// Snap to the visible minor grid when no object point is near.
    pub snap_grid: bool,
}

impl Default for Prefs { /* format_version: PREFS_FORMAT_VERSION, both true */ }

impl Prefs {
    /// Missing file → defaults. Never writes. Unknown fields are ignored, missing ones take the default.
    pub fn load(path: &Path) -> Result<Prefs, ProjectError>;
    /// Atomic write (old file kept as `prefs.json.bak` by `atomic_write`).
    pub fn save(&self, path: &Path) -> Result<(), ProjectError>;
}
```

`from_versioned_json(&text, PREFS_FORMAT_VERSION, no_migrate)?` then set `format_version = PREFS_FORMAT_VERSION`.
`save` = `atomic_write(path, to_checked_json(self)?.as_bytes())`. `lib.rs`: `mod prefs;`
`pub use prefs::{Prefs, PREFS_FORMAT_VERSION};`. Saved text (exact):
```

  "snap_objects": true,
  "snap_grid": false
}
```

  ```rust
  /// The visible minor grid step in mm (canvas lines and grid snapping use the same value).
  pub fn grid_step(&self) -> f64 {
      grid_step(self.view.zoom, self.project.units, view::GRID_MIN_PX)
  }

  /// Grid node near `p` when "Snap to grid" is on.
  fn grid_at(&self, p: Point) -> Option<Snap> {
      self.prefs.snap_grid.then(|| Snap { p: snap::grid_snap(p, self.grid_step()), kind: SnapKind::Grid, item: 0 })
  }

  /// The shared snap rule of the drawing tools, Measure and Set origin: object (pref on, within `radius`) → grid
  /// (pref on) → None.
  pub fn snap_point(&self, p: Point, radius: f64) -> Option<Snap> {
      self.prefs.snap_objects.then(|| self.snap_at(p, radius)).flatten().or_else(|| self.grid_at(p))
  }

  /// A primary click of a non-Select, non-Round-corners tool at the raw world point `w`, snapped by `snap_point`
  /// (radius SNAP_PX / zoom). With both snap options off the raw point counts as snapped (Set origin).
  pub fn snapped_click(&mut self, w: Point) {
      let snap = self.snap_point(w, snap::SNAP_PX / self.view.zoom as f64);
      let free = !self.prefs.snap_objects && !self.prefs.snap_grid;
      self.canvas_click(snap.map_or(w, |sn| sn.p), snap.is_some() || free);
  }

  /// The key point a drag starting at `p` would grab (rule in specs/M20.md, decision 1); None = no move would start.
  pub fn grab_at(&self, p: Point, pick_tol: f64) -> Option<Snap>;

  /// Saves at once when changed; never an undo step, never dirty. A failed save keeps the value and warns.
  pub fn set_prefs(&mut self, p: Prefs);
  ```

  `!sel && self.tab_markers().iter().any(|(m, _, _)| *m == hit)` → None; else
  `Some(snap::nearest(&self.snap_cache.cands, &self.project.items, |i| if sel { self.selection.contains(&i.id) } else { i.id == hit }, p, f64::INFINITY).unwrap_or(Snap { p, kind: SnapKind::Point, item: hit }))`.

## Risks
- **Behaviour change for every free click:** grid snap is on by default, so clicks away from objects land on the
  grid (drawing, Measure, Set origin). Intended by the user; the checkbox turns it off.
- **Jump on grab** (decision 2) could surprise when pressing far from any key point of a big DXF contour; the hover
  marker is the mitigation.
- **Test churn**: about 15 M15 tests change; the "grid-only" fixes must not hide real regressions (rule above).
- A **newer** `prefs.json` (future version) is reported and replaced by the defaults on the next toggle (the old
  file stays as `prefs.json.bak`).
- `grab_at` runs every frame while hovering (pick + tab markers + a scan of the snap cache): fine for the bracket and
  the 2500-line test sizes; watch huge DXFs.
- Settings window height at 1280×800 (fallback in "panels.rs").
