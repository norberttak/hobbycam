# M3 – Project file & tool inventory (`hc-project`)

## Scope
**In:** `Tool` + `ToolLibrary` (JSON in the user config dir), `Project` (`.hcam` JSON) with stock, machine settings, drawing items, embedded tools and operations, version check + migration hook, reference validation, atomic save, mm/inch helpers and the length-input parser, DXF import → project items.
**Out:** GUI (M4), toolpaths (M5), tab placement (M6, only its settings are stored here), value-range checks (M8), text items (M10, but see the versioning rule).

## Crate
`crates/hc-project`. Deps: `hc-geom`, `hc-dxf` (path), `serde` (derive), `serde_json = { version = "1", features = ["float_roundtrip"] }`, `directories = "6"` (MIT/Apache, no system lib).
`float_roundtrip` is required: without it serde_json's parser can be off by 1 ULP, so loaded values would not equal the saved ones.
Tests use `env!("CARGO_TARGET_TMPDIR")` for scratch files, so no `tempfile` dependency is needed.

| module | content |
|---|---|
| `tool.rs` | `Tool`, `ToolKind`, `ToolLibrary`, `default_library_path` |
| `project.rs` | `Project`, `Stock`, `Machine`, `Item`, `Operation`, …, load/save, validate, `add_dxf` |
| `units.rs` | `Units`, `to_display`, `from_display`, `parse_length` |
| `io.rs` | `atomic_write`, version check + `migrate` |

All public data types derive `Debug, Clone, PartialEq, Serialize, Deserialize`. Enums use `#[serde(tag = "type", rename_all = "snake_case")]` and fields use `snake_case`. All lengths are in **mm**, feeds in **mm/min**, angles in **degrees** (only the V-bit angle), rpm as `u32`.

## Data
```rust
pub struct Tool {
    pub id: u32,                 // tool number, shown "T<n>", emitted as T<n> M6; unique in a library/project; > 0
    pub name: String,
    pub kind: ToolKind,          // FlatEndMill | BallEndMill | VBit { angle_deg: f64 } | Drill
    pub diameter: f64, pub flute_length: f64, pub flutes: u32,
    pub feed: f64, pub plunge_feed: f64, pub rpm: u32, pub depth_per_pass: f64, pub stepover_pct: f64,
    #[serde(default)] pub comment: String,
}
pub struct ToolLibrary { pub format_version: u32, pub tools: Vec<Tool> }   // kept sorted by id
impl ToolLibrary {
    fn load(path: &Path) -> Result<ToolLibrary, ProjectError>;  // missing file -> Ok(empty); corrupt -> Err(Json), file untouched
    fn save(&self, path: &Path) -> Result<(), ProjectError>;    // atomic_write
    fn get(&self, id: u32) -> Option<&Tool>;
    fn add(&mut self, t: Tool) -> Result<(), ProjectError>;     // Err(DuplicateToolId) / Err(InvalidToolId) for 0
    fn update(&mut self, t: Tool) -> Result<(), ProjectError>;  // by id; Err(NoSuchTool)
    fn remove(&mut self, id: u32) -> Option<Tool>;
    fn next_free_id(&self) -> u32;                              // max + 1, 1 when empty
}
pub fn default_library_path() -> Option<PathBuf>; // directories::ProjectDirs::from("", "", "HobbyCAM")?.config_dir()/tools.json

pub struct Project {
    pub format_version: u32,           // FORMAT_VERSION = 1
    pub units: Units,                  // Mm | Inch, display only
    pub stock: Stock,                  // { min_x, min_y, width, height, thickness, origin: WorkOrigin }
    pub machine: Machine,              // { safe_z: 5.0, clearance_z: 2.0, post: "linuxcnc" } (defaults)
    pub layers: Vec<LayerInfo>,        // { name, color: i16 } from DXF import, first-seen order
    pub items: Vec<Item>,
    pub tools: Vec<Tool>,              // copies; the project's copy wins over the library
    pub operations: Vec<Operation>,    // execution order = Vec order (M5 groups by tool)
    pub next_id: u64,                  // shared counter for item and operation ids; ids are never reused
}
pub enum WorkOrigin { DrawingOrigin, StockBottomLeft, StockCenter }   // XY zero; Z0 is always the stock top
pub struct Item { pub id: u64, pub layer: String, pub source: Source, pub geom: Geom }
pub enum Source { Imported { file: String }, Drawn }
pub enum Geom { Contour(Contour), Point(Point) }   // M10 adds e.g. Text { .. } (see Versioning)

pub struct Operation {
    pub id: u64, pub name: String, pub enabled: bool,
    pub tool: u32, pub items: Vec<u64>,
    pub kind: OpKind,                  // Engrave | Contour { side: Side, direction: Direction } | Pocket { stepover_pct } | Drill { peck: Option<f64> }
    pub depth: f64,                    // positive = below stock top
    pub depth_per_pass: f64, pub feed: f64, pub plunge_feed: f64, pub rpm: u32,
    pub tabs: Tabs,                    // { enabled: false, placement: Count(4) | Spacing(f64), width: 5.0, height: 1.0 }
}
pub enum Side { Inside, Outside, On }   pub enum Direction { Climb, Conventional }
```
- `Project::new()` gives defaults (mm; stock 100×100×10 at (0,0), origin DrawingOrigin; machine as above; `next_id` 1).
- `Project::add_dxf(&mut self, imp: &DxfImport, file: &str) -> Vec<u64>` creates one `Item` per contour and per point (layer kept, `Source::Imported`), adds missing `LayerInfo`s and returns the new ids.
- `Project::add_operation(&mut self, name, kind, tool: &Tool, items: Vec<u64>) -> u64` copies the tool into `tools` if its id is absent, and fills depth_per_pass/feed/plunge/rpm from the tool. Pocket `stepover_pct` comes from the tool. `depth` defaults to `tool.depth_per_pass` (the user edits it).
- `Project::remove_item(id)` also removes the id from every operation's `items`. `remove_operation(id)`.
- `Project::unused_tools()` / `prune_tools()`: drop embedded tools that no operation references (called before save by the app; not automatic).

## Load / save / versioning
- `Project::load(path) -> Result<(Project, Vec<Problem>), ProjectError>`; `Project::from_json(&str)` gives the same without I/O. Steps: parse to `serde_json::Value` → read `format_version` (missing → `Err(MissingVersion)`; `> FORMAT_VERSION` → `Err(VersionTooNew { found, supported })`) → `migrate(value, found) -> Result<Value>` (v1: identity; this is the hook) → `serde_json::from_value` → `validate()`.
- **Versioning rule (this challenges the input):** there are no major/minor numbers, just one `u32`. Any newer version is refused. Additive fields go in with `#[serde(default)]` and need **no** bump. A new enum variant (e.g. `Geom::Text` in M10) **is** a bump, so an old app refuses the file with the version error. There is **no catch-all `Unknown` variant**: it would silently drop the user's data on re-save. serde's own "unknown variant `text`" error stays as the fallback.
- `validate(&self) -> Vec<Problem>` is **non-fatal**. Load succeeds and returns the problems; the GUI shows them and M8 blocks export. Problems: `MissingTool { op, tool }`, `MissingItem { op, item }`, `DuplicateId(u64)`, `DuplicateToolId(u32)`, `IdNotBelowNextId(u64)`. Refusing to open a project over a dangling reference would lock the user out of their own work.
- `Project::save(&self, path)` / `to_json()`: `serde_json::to_string_pretty` + `"\n"`, then **re-parse the bytes before writing** (NaN/inf serialise as `null` and would make the file unloadable; the save becomes `Err(NonFinite)`), then `atomic_write`.
- `atomic_write(path, bytes)`: if `path` exists, `fs::copy` it to `<path>.bak` (overwriting the old .bak), write `<path>.tmp` in the same directory, `sync_all`, then `fs::rename` it onto `path` (this replaces the target on Windows too). This covers "never silently overwrite a corrupt library": its last content survives as `.bak`, and `load` never writes.
- `ProjectError { Io(io::Error), Json(serde_json::Error), MissingVersion, VersionTooNew { found: u32, supported: u32 }, NonFinite, DuplicateToolId(u32), InvalidToolId, NoSuchTool(u32) }`, with Display + Error. The Json message includes line/column.
- The library file uses the same version check (`format_version` 1).

## Units (`units.rs`)
`pub enum Units { Mm, Inch }`, `to_display(mm, Units) -> f64`, `from_display(v, Units) -> f64` (25.4 exactly).
`parse_length(s: &str, default: Units) -> Option<f64>` returns mm. Trim; optional suffix `mm`, `in`, `"` (case-insensitive, space allowed). The number may be a decimal (`.` or `,` as separator), a fraction `a/b`, or mixed `w a/b`. No suffix → `default` units. Empty, `b = 0`, non-finite or trailing garbage → `None`. Negative numbers are accepted (the caller decides).

## Acceptance tests
1. Bracket: `add_dxf(import(bracket), "Bracket.dxf")` → 29 items (contours: Outline 12 + Center 11 + Hidden 1 + Title 5; Bracket has no points), 4 `LayerInfo` with the M2 colours. Ids 1..=29, `next_id` 30.
2. Bracket round-trip: add a Pocket op on the outer contour item and a Drill op on the 4 hole items with T1 → `from_json(to_json(p)) == p` (exact `PartialEq`, no tolerance) and the problems list is empty.
3. Float exactness: a tool with diameter `0.1 + 0.2`, feed `1.0/3.0`, depth `25.4 * 0.3125`, stock thickness `1e-300` → round-trip bit-identical (`to_bits`).
4. Golden: `from_json(small_v1.hcam)` equals the project built in code, and `to_json` of that project equals the file byte for byte.
5. Version: `format_version: 2` → `VersionTooNew { found: 2, supported: 1 }`; field missing → `MissingVersion`; `migrate(v, 1)` returns `v` unchanged.
6. Unknown item type `{"type":"text",…}` with version 1 → `Err(Json)` whose message contains `text`.
7. Dangling: an op with tool 9 (not embedded) and item 999 → load is `Ok`, problems = [`MissingTool{op, tool: 9}`, `MissingItem{op, item: 999}`]. Two items with the same id → `DuplicateId`.
8. `remove_item(id)` removes the id from the ops; a later `add_dxf` never reuses it.
9. `add_operation` with tool T2 (feed 800, plunge 200, rpm 18000, dpp 1.0, stepover 40) → the op has those values, and `tools` contains T2 exactly once after two ops.
10. Library: missing file → empty; save + load round-trip; `add` of a duplicate id → `DuplicateToolId`; id 0 → `InvalidToolId`; `update` of a missing id → `NoSuchTool`; `next_free_id` with {1,2,5} → 6; `tools` stays sorted after `add`.
11. Corrupt library (`{"format_version":1,"tools":[{`) → `Err(Json)`, and the file bytes are unchanged afterwards. Then `save` of a new library → the new file loads, and `tools.json.bak` holds the corrupt bytes.
12. Atomic save: after `save`, no `.tmp` file remains; saving over an existing file leaves `.bak` = the previous content. A save into a non-existent directory → `Err(Io)`, nothing created.
13. NaN depth → `save` returns `Err(NonFinite)`, and an existing target file is unchanged.
14. Units: `parse_length("6.35mm", Inch)` = 6.35; `"0.25in"`, `"1/4\""`, `"1/4"` with Inch → 6.35; `"1 1/2", Inch` → 38.1; `"6,35", Mm` → 6.35; `"3", Mm` → 3; `"abc"`, `"1/0"`, `""`, `"5 mmx"` → None. `to_display(25.4, Inch)` = 1.0.
15. `default_library_path()` ends with `tools.json` and contains `HobbyCAM` (when it is Some).

## Risks / notes
- Item ids are global and never reused; a project with many re-imports grows `next_id`. That is harmless with u64.
- Mac App Store sandbox: `directories` resolves into the app container automatically. No change is needed, but check it in M12.
- Embedded tool copies can diverge from the library. The project copy wins; a "refresh from library" action is M4 GUI work.
- Contours are stored fully, so a 1 MB DXF gives a few MB of JSON. That is fine for hobby use; no compression.
