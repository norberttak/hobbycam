# M12 – Release

## Scope
**In:** CI on push/PR (fmt, clippy, test on macOS + Windows, licence gate, workflow/script lint, mdBook build, Pages deploy on
`main`); a release workflow on tag `v*` (plus a manual dry run) that builds a Windows x86_64 `.zip` and a macOS Apple-silicon (`aarch64-apple-darwin`) `.dmg`
(signed + notarized when the secrets exist) and creates a **draft** GitHub Release with `SHA256SUMS` and notes from `CHANGELOG.md`;
an original app icon; a `cargo-about` third-party licence report shipped in both packages; a local, scripted Mac App Store build
(`appstore` cargo feature, sandbox, `.pkg`); `RELEASING.md` (step-by-step for the user); the Download section of `install.md`;
`PRIVACY.md`; `CHANGELOG.md`; one Rust test module that keeps the release files consistent.

**Out:** Windows code signing (no certificate; SmartScreen warning is documented), Windows on ARM builds (x64 runs under emulation),
Linux packages, an installer for Windows (MSI), auto-update, Homebrew/winget, App Store upload from CI, Apple ID password
authentication, `cargo-bundle`/`cargo-packager` (plain scripts instead, see "Decisions"), file-type association / double-click
opening of `.hcam`/`.dxf` (winit does not deliver macOS open-document events; `CFBundleDocumentTypes` would promise something the
app cannot do), Dependabot, an About dialog.

**Nothing in M12 pushes, tags, uploads or creates a release on its own.** The repo has no remote. Every network step is run by
the user and listed in "User-run steps". The coder and tester must not run `git push`, `gh repo create`, `gh release`, `notarytool`,
`altool` or Transporter.

## Decisions
| # | topic | decision | why |
|---|---|---|---|
| D1 | Bundling | plain shell scripts (`scripts/macos-*.sh`) + Info.plist template; no cargo-bundle | one binary, one icns, one plist; no extra tool to pin; same script runs locally and in CI |
| D2 | Action pinning | every `uses:` pinned to the full 40-char commit SHA with a `# vX.Y.Z` comment (versions below); the coder resolves SHAs with `git ls-remote --tags` | release job holds signing secrets; tags can move |
| D3 | Toolchain | `rust-toolchain.toml` pins `1.99.1` (+ rustfmt, clippy); no toolchain action (rustup on the runners reads the file) | new clippy lints cannot break a release tag |
| D4 | Caching | `Swatinem/rust-cache` in CI only; release jobs build clean, no cache | no cache poisoning into signed artifacts |
| D5 | Shot tests | stay `#[ignore]`, not run in CI | GitHub macOS runners have a paravirtual GPU, Linux needs lavapipe; pixels differ per driver; they produce docs images, not regressions. Non-shot kittest tests use the lazy renderer and need no GPU |
| D6 | Ubuntu | no Rust test job on Ubuntu (not a target platform); Ubuntu runs docs, licences and lint only | cheap jobs that need no build |
| D7 | Windows | x86_64 only, MSVC, `+crt-static` via `.cargo/config.toml` (all builds, so the tested binary = the shipped one); exe icon + version resource via `winresource` build-dependency | no VC++ redistributable; Windows on ARM runs x64 under emulation |
| D8 | macOS | Apple silicon only (`aarch64-apple-darwin`, no Intel, no `lipo`), `MACOSX_DEPLOYMENT_TARGET=11.0`, `LSMinimumSystemVersion` 11.0 | user decision 2026-10-27; one target, fewer moving parts |
| D9 | Bundle id | `io.github.norberttak.hobbycam` | matches the GitHub Pages domain the user owns; **cannot change** once an App Store record exists (confirmed by the user 2026-10-27) |
| D10 | Signing (Developer ID) | hardened runtime, `--timestamp`, no entitlements; notarize the `.dmg` with `notarytool` + App Store Connect API key; staple the `.dmg` | API key avoids Apple ID password + 2FA in CI |
| D11 | No secrets (forks, dry runs) | app ad-hoc signed (`codesign --sign -`), dmg named `…-unsigned.dmg`, a `::warning::` annotation; release still drafted. **Partial** secrets (some but not all of the six) fail the job | forks work; misconfiguration is loud |
| D12 | Release | `gh release create --draft --verify-tag`; user reviews and publishes by hand | nothing goes public by itself |
| D13 | Version | single source: `[workspace.package] version`; tag must equal it; `CHANGELOG.md` must have its section; Info.plist gets it from the script; path deps lose their `version =` (all crates `publish = false`) | bumping is a one-line edit |
| D14 | Licence report | `cargo-about` (generate fails on any non-accepted licence, so it is check + report in one tool); no cargo-deny | one tool |
| D15 | App Store build | local script `scripts/macos-appstore.sh` on the user's Mac (certs in the login keychain), upload with Transporter; no CI workflow | two more certs + a profile in CI for a once-per-release step is not worth it |
| D16 | Sandbox file access | see "App Store build": `atomic_write` falls back to an in-place write when the sibling `.tmp`/`.bak` is denied (all builds, runtime); with feature `appstore` G-code export asks for a **folder** | the sandbox grants only the user-selected file; export writes several files |
| D17 | Icon | original design drawn in Rust with `tiny-skia` (already in `Cargo.lock`, BSD-3-Clause) in an ignored generator test; PNG/ICO committed, ICNS via `iconutil` | no SVG renderer dependency; CPU-only, no GPU |
| D18 | Guides | `RELEASING.md` at repo root (maintainer guide, not in the user manual); user-facing download text in `docs/src/install.md` | the manual is for machinists, not maintainers |
| D19 | Privacy policy | `PRIVACY.md` at repo root ("HobbyCAM collects no data…"), URL `https://github.com/norberttak/hobbycam/blob/main/PRIVACY.md` | App Store requires a privacy URL; keeps the manual at 14 pages (docs_check unchanged) |

Pinned versions (latest at spec time, 2026-10-27): `actions/checkout` v7.0.1, `Swatinem/rust-cache` v2.9.3,
`taiki-e/install-action` v2.87.32, `actions/configure-pages` v6.0.0, `actions/upload-pages-artifact` v5.0.0,
`actions/deploy-pages` v5.0.1, `actions/upload-artifact` v7.0.2, `actions/download-artifact` v8.0.2; tools via
`taiki-e/install-action` (prebuilt, checksum-verified): `mdbook@0.5.4`, `cargo-about@0.9.3`, `actionlint@1.7.12`; `winresource`
0.1.34. If install-action lacks a prebuilt for a tool, fall back to `cargo install --locked <tool>@<same version>`.

## Release – `.github/workflows/release.yml`
`on: push: tags: ['v*']` and `workflow_dispatch` (dry run: builds and uploads workflow artifacts, never a release).
Top-level `permissions: contents: read`. Env `CARGO_TERM_COLOR: always`.

1. **`check`** (ubuntu-latest): `V` from `cargo pkgid`; on a tag fail unless `${GITHUB_REF_NAME#v} == V`; fail unless
   `CHANGELOG.md` has a line starting `## [$V]`; extract that section (up to the next `## [`) into `notes.md`; install
   cargo-about, generate `THIRD-PARTY-LICENSES.html`; upload both as artifact `meta`. Output `version`.
2. **`windows`** (windows-latest, needs check, `shell: pwsh`): download `meta`; `cargo test --workspace --release`;
   `cargo build --release -p hobbycam`; fail if `Select-String -Path target\release\hobbycam.exe -Pattern 'VCRUNTIME140' -SimpleMatch -Quiet`
   is true (static CRT check); folder `HobbyCAM-$V-windows-x86_64\` with `hobbycam.exe`, `LICENSE.txt` (copy of `LICENSE`),
   `README.md`, `THIRD-PARTY-LICENSES.html`, `PHOSPHOR-LICENSE.txt`, `HERSHEY-NOTICE.txt`; `Compress-Archive` →
   `dist\HobbyCAM-$V-windows-x86_64.zip` (the zip contains the folder); upload artifact `windows`.
3. **`macos`** (macos-latest, needs check): download `meta`; `rustup target add aarch64-apple-darwin`;
   `cargo test --workspace --release`; if all six secrets are set, import the `.p12` into a temporary keychain (random password,
   `security create-keychain/set-keychain-settings -lut 3600/import -T /usr/bin/codesign/set-key-partition-list -S apple-tool:,apple:/list-keychains -d user -s`)
   and write the API key to `$RUNNER_TEMP/AuthKey.p8`; none set → unsigned path (D11); some set → fail listing the missing names.
   Then `THIRD_PARTY=meta/THIRD-PARTY-LICENSES.html scripts/macos-build.sh` and `scripts/macos-dmg.sh` with the signing env;
   upload artifact `macos`; `if: always()` delete the keychain and the key file.
4. **`publish`** (ubuntu-latest, `if: startsWith(github.ref, 'refs/tags/v')`, needs windows + macos, `permissions: contents: write`):
   download all; `sha256sum *.zip *.dmg > SHA256SUMS`; `gh release create "$GITHUB_REF_NAME" --draft --verify-tag
   --title "HobbyCAM $V" --notes-file notes.md <zip> <dmg> SHA256SUMS` with `GH_TOKEN: ${{ github.token }}`.

## macOS scripts
**`scripts/macos-build.sh [--appstore] [BUILD]`** (`BUILD` defaults to `V`; App Store re-uploads of one version need a higher BUILD):
`export MACOSX_DEPLOYMENT_TARGET=11.0`; `cargo build --release -p hobbycam --target aarch64-apple-darwin`
(add `--features appstore` with `--appstore`); create `target/macos/HobbyCAM.app/Contents/{MacOS,Resources}`;
binary → `MacOS/hobbycam`; `sed` the template replacing `@VERSION@`, `@BUILD@` → `Contents/Info.plist`; `plutil -lint`;
`app/assets/icon/hobbycam.icns` → `Resources/hobbycam.icns`; `LICENSE`, `README.md`, the two font notices and `$THIRD_PARTY`
(required in CI: if `THIRD_PARTY` is set the file must exist; if unset print a warning and skip) → `Resources/`.

**`scripts/macos-dmg.sh`** env: `MACOS_SIGNING_IDENTITY` (optional), `NOTARY_KEY_PATH`, `NOTARY_KEY_ID`, `NOTARY_ISSUER` (all three
or none; require the identity). Signed: `codesign --force --options runtime --timestamp --sign "$ID" HobbyCAM.app` (one Mach-O, no
`--deep`); unsigned: `codesign --force --sign - HobbyCAM.app`. Run `check-macos-bundle.sh`. Stage `HobbyCAM.app`, a symlink
`Applications -> /Applications` and `LICENSE.txt`; `hdiutil create -volname "HobbyCAM $V" -srcfolder stage -format UDZO -ov`
→ `dist/HobbyCAM-$V-macos-arm64.dmg` (`…-unsigned.dmg` unsigned); signed: `codesign --timestamp --sign "$ID"` the dmg; with
notary vars: `xcrun notarytool submit <dmg> --key … --key-id … --issuer … --wait` (fail on status ≠ Accepted, print
`notarytool log` on failure), `xcrun stapler staple <dmg>`, `xcrun stapler validate <dmg>`,
`spctl -a -t open --context context:primary-signature -vv <dmg>`.

**`scripts/check-macos-bundle.sh <app>`** (exit 1 with a message per failure): Info.plist lint ok; `CFBundleShortVersionString` == `V`
(via `/usr/libexec/PlistBuddy -c Print:…`); `CFBundleIdentifier` == `io.github.norberttak.hobbycam`; `Contents/MacOS/hobbycam`
executable; `lipo -archs` prints exactly `arm64`; `Resources/hobbycam.icns` exists; `codesign --verify --strict` passes
(ad-hoc included); if signed with a Team ID, `codesign -d --verbose=2` shows `flags=0x10000(runtime)`.

**`packaging/macos/Info.plist`** keys: `CFBundleName` HobbyCAM, `CFBundleDisplayName` HobbyCAM, `CFBundleIdentifier`
io.github.norberttak.hobbycam, `CFBundleExecutable` hobbycam, `CFBundleIconFile` hobbycam, `CFBundlePackageType` APPL,
`CFBundleShortVersionString` @VERSION@, `CFBundleVersion` @BUILD@, `CFBundleInfoDictionaryVersion` 6.0,
`LSMinimumSystemVersion` 11.0, `LSApplicationCategoryType` public.app-category.graphics-design, `NSHighResolutionCapable` true,
`NSHumanReadableCopyright` "© 2026 Norbert Takacs. GPL-3.0-or-later.", `ITSAppUsesNonExemptEncryption` false.

## App Store build
**Code (feature `appstore`, macOS sandbox):**
- `crates/hc-project/src/io.rs` `atomic_write` (runtime, every build, no feature): if copying to `<path>.bak` or creating
  `<path>.tmp` fails with `ErrorKind::PermissionDenied` (sandbox denials are EPERM, mapped to that kind), and `path` exists:
  read the old bytes into memory, write `path` in place (`File::create` + `write_all` + `sync_all`); on a write error try to
  restore the old bytes, then return the original error. No `.tmp` or `.bak` is left. A new file in a denied directory still errors.
  Doc comment updated. Effect: in the App Store build, saving a project and exporting have **no `.bak`** next to the project.
- `app/src/main.rs` `write_export`: under `#[cfg(feature = "appstore")]` the save dialog is replaced by
  `rfd::FileDialog::new().set_title("Choose the folder for the G-code files").pick_folder()` and `base = folder.join(format!("{stem}.{ext}"))`
  (name = project stem; the folder grant covers all segment files, their `.bak`s and the stale-file scan). The non-appstore path
  is unchanged.
- Tool library: `directories` resolves into the container (`~/Library/Containers/io.github.norberttak.hobbycam/Data/Library/Application Support/HobbyCAM/`)
  because the sandbox sets `HOME`; no code change. Not shared with the .dmg build (documented).
- Help → User manual: `open_url` goes through LaunchServices; no network entitlement (verify in U9).

**`packaging/macos/appstore.entitlements`**: `com.apple.security.app-sandbox` true, `com.apple.security.files.user-selected.read-write`
true, `com.apple.application-identifier` `@TEAM_ID@.io.github.norberttak.hobbycam`, `com.apple.developer.team-identifier` `@TEAM_ID@`.
Nothing else (no network, no JIT).

**`scripts/macos-appstore.sh`** env: `APPSTORE_TEAM_ID`, `APPSTORE_APP_IDENTITY` ("Apple Distribution: … (TEAM)"),
`APPSTORE_INSTALLER_IDENTITY` ("3rd Party Mac Developer Installer: … (TEAM)", the "Mac Installer Distribution" cert),
`APPSTORE_PROFILE` (path to the "Mac App Store Connect" provisioning profile), optional arg `BUILD`. Steps: `macos-build.sh --appstore BUILD`;
copy the profile to `Contents/embedded.provisionprofile`; entitlements from the template with `@TEAM_ID@` substituted;
`codesign --force --timestamp --options runtime --entitlements ent --sign "$APPSTORE_APP_IDENTITY" HobbyCAM.app`;
`codesign -d --entitlements - ` shows app-sandbox; `productbuild --component HobbyCAM.app /Applications --sign "$APPSTORE_INSTALLER_IDENTITY"
dist/HobbyCAM-$V-appstore.pkg`; `pkgutil --check-signature`. It never uploads.

**Upload (user, `RELEASING.md`):** primary: **Transporter** app (free, Mac App Store), sign in, drag the `.pkg`, Deliver.
CLI alternative: `xcrun altool --upload-package <pkg> --type macos --apiKey <id> --apiIssuer <issuer>` (key in
`~/.appstoreconnect/private_keys/`). Careful wording in the guide: altool's *notarization* commands were retired in Nov 2023
(`notarytool` replaced them); its *upload* commands still worked at the time of writing but Apple steers users to Transporter/Xcode,
so if altool reports it is unavailable, use Transporter. `notarytool` cannot upload to the App Store.

## Icon
`app/src/icon_gen.rs`:
- `#[test] #[ignore] fn make_icons()`: draws the icon with tiny-skia at each size directly from the vector description (not by
  resizing): transparent 1024 canvas; rounded square inset 100 px, corner radius 185, fill slate `#2E4057`; an orange `#F28C28`
  rounded-rectangle contour (inset 270, radius 60, stroke 56, round caps) with one gap of 90 px centred on the top edge (a tab);
  a white filled circle Ø220 (the cutter) centred on the contour's bottom-right corner, with a slate dot Ø40 at its centre.
  Coordinates scale with size. Writes into `$HOBBYCAM_ICON_DIR`: `icon_16x16.png` … `icon_512x512@2x.png` (the 10 iconset
  names), `hobbycam-1024.png`, `hobbycam-256.png`, and `hobbycam.ico` (PNG-compressed entries 16, 32, 48, 256; hand-written
  6-byte header + 16-byte directory entries, width/height byte 0 = 256).
- `#[test] fn icon_assets_valid()` (runs in CI): `hobbycam.ico` header type 1, count 4, sizes 16/32/48/256, each blob starts with
  the PNG signature and its IHDR size matches the entry; `hobbycam.icns` starts with `icns` and its length field equals the file
  size; `hobbycam-256.png` decodes (via `eframe::icon_data::from_png_bytes`) to 256×256.
- `scripts/make-icons.sh`: `HOBBYCAM_ICON_DIR=target/icon/HobbyCAM.iconset cargo test -p hobbycam make_icons -- --ignored`;
  copy the three PNG/ICO assets into `app/assets/icon/`; `iconutil -c icns target/icon/HobbyCAM.iconset -o app/assets/icon/hobbycam.icns`.
- The design is original (generic cutter-on-contour motif); do not look at `images/` or any other CAM product's icon.

## `docs/src/install.md` – Download
- **Windows 10/11 (64-bit)**: download `HobbyCAM-<version>-windows-x86_64.zip`, right-click → Extract All, run `hobbycam.exe`.
  Unsigned, so SmartScreen shows "Windows protected your PC" → **More info** → **Run anyway** (once). Nothing to install, no
  VC++ runtime; delete the folder to uninstall. Runs on Windows on ARM through emulation.
- **Apple silicon Macs (M1 or later), macOS 11 or later** (Intel Macs are not supported): open the `.dmg`, drag HobbyCAM to Applications. It is notarized by Apple, so it
  opens normally. A build named `…-unsigned.dmg` (from a fork) is blocked: System Settings → Privacy & Security → **Open Anyway**.

## Risks
- R1 Windows build paths (`winresource` needs `rc.exe` from the Windows SDK; present on `windows-latest` and with VS Build Tools) are first exercised in CI (U2).
- R2 `cargo-about` licence-id matching (`Ubuntu-font-1.0`, `Apache-2.0 WITH LLVM-exception`, `MIT/Apache-2.0` legacy syntax) may need `[[clarify]]`/`workarounds` entries; the coder adds them and records why.
- R3 Apple tooling drifts: altool upload availability, minimum SDK for App Store uploads (build App Store pkgs with the current Xcode), possible future requirement for asset-catalog icons instead of `.icns`. RELEASING.md states the date it was written.
- R4 Runner images change (`macos-latest`, `windows-latest` move); pinned toolchain limits the blast radius. GPU-less Windows VMs may fail to start wgpu (not a release blocker; note in limitations if it shows up).
- R5 **GPL vs App Store:** the FSF's position is that the App Store terms add restrictions incompatible with GPL §10 (VLC was pulled in 2011 for this). The user, as the sole copyright holder, may distribute his own code on any terms, so the App Store build is fine **today** (no third-party GPL/LGPL code; cargo-about rejects any). External contributions would make others copyright holders: README gets one line — "Contributions are accepted under GPL-3.0-or-later and you agree that they may also be distributed through app stores." — and the guide says to keep it that way or stop App Store releases.
- R6 Sandbox behaviour differences (no `.bak`, folder export) exist only in the App Store build and are documented; the `atomic_write` fallback also applies in non-sandboxed builds when a directory is read-only but the file is writable (acceptable, it only makes a save succeed that failed before).
- R7 Release dry runs with secrets on `workflow_dispatch` can be triggered by anyone with write access only; forks never see secrets.
