# M13 – Properties pane follows the last selection (bug fix)

Branch `fix/properties-pane`. App crate only; no project format change, no new dependency.

## Scope
**In:** the Properties pane shows what was selected last — an operation (op list, Issues row, New operation) or canvas
geometry (click, box, newly drawn shape); the pane is hidden when nothing is selected and no drawing tool is active.
Docs in `docs/src`.

**Out:** any other Properties content or layout change, multi-op selection, a "pick geometry for this op" mode, the
Settings window (M14), moving/editing elements (M15).

## Root cause
`AppState` keeps two independent selections (`app/src/state.rs` ~line 265): `selection: BTreeSet<u64>` (canvas items) and
`selected_op: Option<u64>`. `panels::right` (`app/src/panels.rs` ~line 934) shows `op_props` whenever `selected_op` is `Some`
and falls back to `selection_props` only when it is `None`. Nothing on the canvas path ever resets `selected_op`:
`click_select`, `box_select` (`state.rs` ~706–736), `add_geoms` (~880, new shapes become the selection) and `escape` (~774) only
touch `selection` / `selected_tab`. `selected_op` is cleared only by `delete_op`, `replace_project` (new/open, ~445) and undo of a removed op.
So once an op was clicked, it wins over every later canvas selection. Bonus symptom: `bracket_clean()` leaves `selected_op` at
the Drill op with an empty selection, i.e. the pane shows an op nobody sees as selected.

## Decisions
| # | topic | decision | why |
|---|---|---|---|
| D1 | Rule | a plain (no `Shift`) canvas selection makes the geometry current: `selected_op = None`, `selected_tab = None` | "last selected wins"; one place in state, canvas.rs unchanged |
| D2 | Shift | `Shift`+click and `Shift`+box keep `selected_op` | keeps the documented **Use current selection** workflow: click the op, Shift-click geometry in/out, press the button |
| D3 | Tabs | a plain click whose hit is an item of the current tab op (`tab_markers()` contains that id) changes nothing (op, selection, tab stay) | the first click of a double-click (= add tab) arrives as a plain `clicked`; clearing the op there would hide the tab markers and break "double-click to add a tab". To see that contour's item properties, press `Esc` first |
| D4 | Esc | `escape()` in Select mode also clears `selected_op` | "nothing selected" must be reachable from the keyboard |
| D5 | Hidden pane | `panels::right` returns before building the panel when the tool is `Select`/`SetOrigin`, `selected_op` is `None` (or a stale id) and `selection` is empty | `View::world_to_screen` uses `rect.min`, so the canvas does not jump when the right panel appears/disappears |
| D6 | Unchanged | `select_op`, `select_issue`, `new_operation`, `delete_op`, `history_moved`, `clear_selection` keep their behaviour | `clear_selection` is used by many tests/fixtures that expect the op to stay; only `escape` gets the extra line |

## Changes (exact)
`app/src/state.rs`
- `click_select(&mut self, p: Point, tol: f64, shift: bool)` — signature unchanged. New body:
  ```rust
  let hit = hit::pick(&self.project.items, |i| self.is_visible(i), p, tol);
  if shift {
      // the op stays current, so the user can edit its geometry for "Use current selection"
      if let Some(id) = hit { if !self.selection.remove(&id) { self.selection.insert(id); } }
      return;
  }
  // first click of a double-click on a tab contour: keep the op so the tab markers stay
  if hit.is_some_and(|id| self.tab_markers().iter().any(|(m, _, _)| *m == id)) {
      return;
  }
  self.selection = hit.into_iter().collect();
  self.selected_op = None;
  self.selected_tab = None;
  ```
- `box_select(..)` — signature unchanged; inside the existing `if !shift { .. }` add `self.selected_op = None; self.selected_tab = None;`.
- `add_geoms(..)` — after `self.selection = ids…` add `self.selected_op = None; self.selected_tab = None;` (a drawn shape is the
  last selection). Doc comment: "the new items become the selection (and the current thing)".
- `escape()` — in the final `else` branch add `self.selected_op = None;` next to `clear_selection()` / `selected_tab = None`.
  Update its doc comment: "…, else clears the selection and the selected operation."

`app/src/panels.rs` — `pub fn right(app: &mut App, ui: &mut Ui)`: before `egui::Panel::right("props")` add
```rust
let s = &app.state;
let drawing = !matches!(s.tool, CanvasTool::Select | CanvasTool::SetOrigin);
let op = s.selected_op.is_some_and(|id| s.project.operations.iter().any(|o| o.id == id));
if !drawing && !op && s.selection.is_empty() {
    return; // nothing selected: no Properties pane
}
```
The rest of `right` stays as it is (the existing `match` already prefers the draw form, then the op, then the selection).

No change to `canvas.rs`, `main.rs` (production part) or the project crates.

## Risks
- D3 means: while a Contour op with tabs is current, a plain click on one of its contours does not switch Properties to that
  item. Accepted (tab editing is the reason the op is current); `Esc` or clicking elsewhere first works.
- Users who used to plain-click geometry and then press **Use current selection** now lose the op on the click; covered by
  the docs change (Shift). If this proves annoying, a later milestone can add an explicit "Pick geometry" mode.
- Hiding the panel changes the central canvas width; mapping is anchored at `rect.min`, so content does not shift, but
  "Zoom to fit" uses the current width — acceptable.
