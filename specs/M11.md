# M11 – User documentation

## Scope
**In:** an mdBook manual in `docs/` (14 short pages, mm and inch), light-theme screenshots made by the offscreen kittest shot
mechanism and committed as PNGs, a sample DXF, one Rust test module that keeps docs and code in sync, a **Help → User manual** menu
entry, README pointer. Audience: a hobbyist with a 3-axis LinuxCNC mill, manual tool change, one `.ngc` per tool, Z re-zeroed per tool.
**Out:** building/deploying the book in CI and GitHub Pages (M12), release download/Gatekeeper/App Store text (M12 fills the
"Download" section of `install.md`), translations, offline help bundled in the binary, an About dialog, video/GIFs, real-window
captures, API/developer docs, any wording, layout or screenshot taken from other hobby-level CAM software (do not open `images/` while writing).

Rules for the writer: describe only what the code does today (the code wins over older specs); every number in the docs comes from
the code (constants listed below); short pages, second person, task-first; units shown as "mm (inch)" only where the value is a
default the user will see, otherwise mm.

## Chapters (`SUMMARY.md` order)
Each page: a title, 1–2 screens of text, at most 2 images. "Must cover" is the minimum; leave out anything not listed unless it is
needed to make a listed step work.

1. `introduction.md` – what HobbyCAM is (2D DXF/drawing → LinuxCNC G-code for a 3-axis mill, manual tool change) and is not (3D,
   automatic toolpaths, other machines, other controllers); the data flow in one line: drawing → select → operation → check →
   simulate → export one file per tool. Image `main-window.png`. Licence line.
2. `install.md` – "Download" (placeholder paragraph: Releases page, Windows .zip, macOS .dmg; M12 completes it) and "Build from
   source" (rustup, `cargo run --release -p hobbycam`, no system libraries needed). Where settings live: tool library
   `tools.json` in the config dir (macOS `~/Library/Application Support/HobbyCAM/`, Windows `%APPDATA%\HobbyCAM\config\`,
   Linux `~/.config/hobbycam/`), previous version kept as `tools.json.bak`.
3. `interface.md` – window tour: menu bar (File, Edit, View, Draw, Settings, Help), left icon sidebar (two columns, tooltips show
   the shortcut, greyed when not usable), canvas (grid, origin arrows, stock rectangle), right panel (operations list with order,
   operation/selection properties, layer list), Issues and messages, status bar (zoom %, "n selected", tool hint "… · Esc cancels").
   Mouse: wheel zoom at the cursor, trackpad two-finger scroll pans and pinch zooms, middle-drag or Space+drag pans, click selects,
   Shift adds, drag a box to select, F zooms to fit. Image `main-window.png` is reused, no second image.
4. `walkthrough.md` – first project with `examples/bracket.dxf` (an inch drawing; imports in mm), exactly the
   `bracket_clean()` project so the screenshots match: add T1 end mill and T2 "Drill 5/8" (Ø15.875) in the tool library; File →
   Import DXF; stock is auto-fitted, check thickness in Settings → Stock; pick the origin (bottom-left corner); select the outer
   contour → New operation → Contour, Outside, depth 10, tabs 4 × 5 mm wide × 2 mm high; select the Ø76.2 and Ø44.45 circles →
   Pocket depth 3; select the four Ø15.875 circles → Drill with T2 depth 10; read the Issues panel (empty); open Simulation;
   File → Export G-code, name `bracket` → files `bracket_1_T1.ngc`, `bracket_2_T2.ngc`; next steps link to `linuxcnc.md`.
   Images `walkthrough-new-op.png`, `walkthrough-toolpaths.png`.
5. `drawing.md` – Line, Rectangle (incl. rounded), Circle, Text by clicks or numeric form; snaps (kinds: end, corner, centre,
   midpoint, intersection, drill point; 10 px capture; marker per kind with its label); Move/Rotate/Scale/Flip (numeric, on the
   selection; scale is uniform), Delete; drawn shapes become plain contours (no parametric edit); Undo/Redo (100 steps, one step
   per drag or field edit). Text: Hershey single-line (open strokes → Engrave) vs. Ubuntu Light outline (closed contours →
   Contour/Pocket); one line, no kerning settings. Images `drawing.png`, `text.png`.
6. `stock-origin.md` – Settings → Stock: width, height, thickness, position; origin presets (drawing origin, stock bottom left,
   stock centre) or "Pick on drawing" / Set origin tool (O): hover until the marker and kind label show, click, Esc cancels.
   Origin only shifts the G-code XY; checks and simulation use the drawing. Z0 is always the top of the stock; depths are positive
   numbers, written as negative Z. Settings → Machine: Clearance Z (default 2 mm, plunge start and drill R plane), Safe Z
   (default 5 mm, rapids between features), Tool change Z (default 40 mm, where each file ends so you can reach the collet).
   Settings → Units: mm/inch changes display and G-code only. Images `stock-menu.png`, `set-origin.png`.
7. `tools.md` – tool library fields (Number, Name, Type flat/ball/V-bit/drill, V angle, Diameter, Flute length, Flutes, Feed,
   Plunge feed, RPM, Depth/pass, Stepover, Comment); the library is global, a project keeps its own copy of used tools so it opens
   on another computer; "Apply tool defaults" in an operation; ball and V-bit are cut as a cylinder of their diameter (no
   V-carve); a drill-type tool can only drill. Image `tool-library.png`.
8. `operations.md` – common fields (Name, Enabled, Tool, Depth, Depth/pass, Feed, Plunge feed, RPM, "Use current selection");
   passes are equal steps each ≤ Depth/pass; straight plunge at Plunge feed (no ramp/helix); operations run in list order;
   consecutive ops with the same tool go into one file. Per kind: Engrave (on the line, open or closed), Contour (Outside/Inside/

9. `tabs.md` – why tabs; enable on a Contour; Count or Spacing, Width, Height; the tool only lifts over a tab on passes below the

### `sanity.md` content
Intro: issues update after every change and again at export; **Error** blocks export ("Cannot export G-code"), **Warning** asks
"Export anyway?". Each issue names the operation; the item is described as e.g. "circle Ø15.875 mm on layer Outline".
Then `## Rules` with exactly one `### <message>` heading per rule, in the order below, placeholders in italics
(e.g. `### Uses tool T*n*, which is not in the project`), and as the **first non-blank line** under it `**Error**` or `**Warning**`,
then "When:" (trigger with the threshold) and "Fix:" (what to do). Rules with several messages list the other variants in the body.

| # | RuleId | sev | message(s) (from `check.rs` / `ToolpathError` Display) | when (code) |
|---|---|---|---|---|
| 1 | MissingTool | E | Uses tool T*n*, which is not in the project | op's tool not embedded |
| 2 | MissingItem | E | Refers to *item*, which does not exist | op lists a deleted item |
| 3 | DuplicateId | E | Id *n* is used more than once | damaged file |
| 4 | DuplicateToolId | E | Tool T*n* is embedded more than once | damaged file |
| 5 | IdCounter | W | Id *n* is not below the id counter | damaged/hand-edited file |
| 6 | InvalidMachine | E | Clearance Z must be greater than 0 · Safe Z must be at or above clearance Z · Tool change Z must be at or above safe Z | Settings → Machine |
| 7 | InvalidStock | E | Stock *width/height/thickness* must be greater than 0 · Stock position *X/Y* must be a finite number | Settings → Stock |
| 8 | InvalidValue | E | Invalid value: *name* | name ∈ depth, depth_per_pass, feed, plunge_feed, stepover_pct, peck, tab_width, tab_height, tab_spacing, tabs, diameter: not a number or ≤ 0; stepover > 100 %; more than 10 000 passes or pocket rings |
| 9 | NoItems | E | No geometry assigned | op has no items |
| 10 | OpenContour | E | Needs closed contours, but got *item* | Pocket, or Contour Inside/Outside, on an open contour |
| 11 | UnsupportedItem | E | Cannot use *item* in this operation | e.g. a point in a Contour, a non-circle in a Drill |
| 12 | ToolTooLarge | E | Tool too large for *item* | offset/pocket produced nothing |
| 13 | DrillBitSideCut | E | T*n* is a drill bit and cannot mill | non-Drill op with a Drill-type tool |
| 14 | DepthBeyondFlutes | E | Depth *d* is deeper than the flute length *l* of T*n* | depth > flute length + 1e-6 mm |
| 15 | SpindleOff | W | Spindle speed is 0 (S0) | RPM 0 |
| 16 | FeedVsTool | W | Feed / Plunge feed *f*/min is far from the tool's *t*/min | > 10× or < 1/10 of the tool default (inch/mm mix-up is 25.4×); Drill checks plunge only |
| 17 | StepoverHigh | W | Stepover *p* % may leave material between rings | Pocket stepover > 50 % |
| 18 | ThroughCut | W | Cuts *x* into the spoilboard (depth *d*, stock *t*) | depth > thickness + 1 mm |
| 19 | TabsNotThrough | W | Tabs are enabled but the cut does not go through the stock | tabs on, depth < thickness |
| 20 | TabTooHigh | W | Tab height *h* is not below the depth *d* | tab height ≥ depth |
| 21 | TabsReduced | W | Only *k* of *n* tabs fit on *item* | contour too short for the count/width |
| 22 | TabsOnOpenContour | W | No tabs on *item*: it is not closed | |
| 23 | NoTabsThroughCut | W | The part may come loose: through-cut without tabs | Outside/On contour, depth ≥ thickness, no tab placed (Inside is exempt: it frees the waste slug) |
| 24 | TabOnCorner | W | Tab *k* sits on a corner and may be weak or misplaced | tab centre within width/2 of a corner (tangent turn > 30°) |
| 25 | DrillSize | W | Hole Ø*d*, drill Ø*t* | drill > hole + 0.05 mm (smaller drills are allowed: pilot/tap) |
| 26 | SharedEdge | W | The *item* touches the *item*: the pocket treats them as one wall | pocket with a nested contour sharing an edge with its boundary (within 1e-6 mm) |
| 27 | OutsideStock | W | Cuts up to *x* outside the stock | a cutting move below Z0 has the tool centre more than radius + 0.001 mm past the stock edge |
| 28 | PocketUncut | W | Parts of *item* are narrower than the tool and stay uncut | area the tool cannot reach, beyond sharp-corner remains, > r² (r = tool radius, mm²) |

After the rules, `## Other messages` (not tested, short list): DXF import warnings (`warning_text`: units assumed mm, not in XY
plane, paper space skipped, missing block, array insert first copy only, spline fit points only, nesting too deep), "Ignored: …",
"no geometry imported", "Exported n file(s): …", "Older files from a previous export are still in the folder: …" (they are never
deleted: remove them by hand so an old "file 3 of 3" is not run).

### `linuxcnc.md` content
- **Files:** one file per tool segment (a run of consecutive enabled ops with the same tool, list order kept). One segment →
  `<name>.ngc`; several → `<name>_<k>_T<n>.ngc`, k zero-padded to the digit count of the total (e.g. `_01_T3` when ≥ 10 files).
  T1 → T2 → T1 gives three files.
- **Inside a file:** header comments `(<name> - file k of n)`, `(Generated by HobbyCAM, LinuxCNC post)`,
  `(Units: mm|inch. Z0 = top of stock. XY0 = <origin>)`, `(Tool: T<n> <name>)`, one `(Op: …)` per op,
  `(Before running: load T<n> <name> and set Z0 on top of stock)`; setup line `G17 G21|G20 G40 G49 G80 G90 G91.1 G94 G98`, then
  `G64 P0.01` (inch `G64 P0.0004`), `G0 Z<safe>`; per spindle speed `S<rpm> M3` + `G4 P2` (2 s spin-up, no at-speed signal);
  arcs `G2/G3` with I/J relative; drills `G81`/`G83 … R<clearance> Q<peck>`; footer `G0 Z<tool change Z>`, `M5`, `M2`. 3 decimals
  in mm, 4 in inch. Not emitted: `T`, `M6`, `M0`, `G43`, coolant, line numbers, `%`. Show the two golden files verbatim with
  `{{#include ../../tests/fixtures/gcode/example_1_T1.ngc}}` and `…example_2_T2.ngc` in ```` ```gcode ```` blocks (if mdBook rejects
  the path outside `src`, copy them to `docs/src/examples/` and add the equality check to test 3).
- **Running a job:** XY0 = the picked origin (header says which); Z0 = stock top, touched off **for every file** because each tool
  sticks out differently (no tool table/G43 needed). Per file: load the named tool, touch off Z (paper/feeler or probe, G10 L20 P1
  Z0 or the Touch Off button), keep XY, run, the machine stops at tool-change Z with the spindle off, change the tool, next file.
- **Before the first run (checklist):** units in the header match the machine; G54 XY at the origin you picked; tool-change Z is
  reachable (below the Z limit after touch-off on thick stock); clamps outside the path (simulation shows the swept area); spoilboard
  under through-cuts; spindle direction/RPM range. **Air cut:** touch off Z 10–20 mm above the stock (or raise G54 Z by that much)
  and run the file once; then real Z0. Watch the first plunge with a hand on E-stop.

### `shortcuts.md` content
One table "Keyboard", one "Mouse", one "Sidebar". Every row: action name exactly as in the app (same `…` character), key in
backticks. Cmd on macOS, Ctrl on Windows/Linux, written `Cmd/Ctrl+Z`.
Keyboard (from `panels.rs`/`canvas.rs`): New `Cmd/Ctrl+N`, Open project… `Cmd/Ctrl+O`, Save `Cmd/Ctrl+S`, Save as… `Cmd/Ctrl+Shift+S`,
Import DXF… `Cmd/Ctrl+I`, Export G-code… `Cmd/Ctrl+E`, Undo `Cmd/Ctrl+Z`, Redo `Cmd/Ctrl+Shift+Z` or `Ctrl+Y`; canvas (plain keys,
canvas hovered, not while typing): Select `Esc` (also cancels a tool), Line `L`, Rectangle `R`, Circle `C`, Text `T`, Set origin `O`,
Zoom to fit `F`, Delete selection `Del` (or Backspace; deletes the selected tab if one is selected).
Sidebar table: every entry of `sidebar_groups` (Select … Units) with its shortcut or "–".

### `limitations.md` content
- Time estimate is typically 10–30 % low: no acceleration, rapids assumed 2500 mm/min, tool changes and touch-off not counted,
  2 s spin-up per speed change counted.
- Straight plunge only (no ramp/helix), no lead-in/out, no rest machining; V-bit/ball treated as cylinders.
- Pocket: uncut areas smaller than r² are not reported; an island closer to a wall than the tool radius is kept 0.0005 mm away
  from it; islands sharing edges with the boundary give SharedEdge.
- Tabs are rectangular lifts on Contour ops only.
- DXF: ASCII DXF R12–2018; no HATCH, dimensions, text entities, binary DXF; layers on/off ignored; tested with AutoCAD 2018 files
  only, **QCAD files are untested** so far (please report problems).
- No machine travel limits, clamp collision check, or multi-line text; drawn shapes are not editable after creation.
- LinuxCNC only; no other controllers.

## Accuracy guard (`app/src/docs_check.rs`, runs in `cargo test`)
Reads files at runtime from `concat!(env!("CARGO_MANIFEST_DIR"), "/../docs/src")` (and the crate sources) with `std::fs`.
- `fn fragments(r: RuleId) -> &'static [&'static str]` – an **exhaustive `match`** (no `_` arm, so a new RuleId does not compile until
  documented) giving the literal parts of each message, first = the heading fragment, e.g. MissingTool → `["which is not in the
  project"]`, InvalidMachine → `["Clearance Z must be greater than 0", "Safe Z must be at or above clearance Z", "Tool change Z must be
  at or above safe Z"]`, InvalidValue → `["Invalid value:"]`, NoItems → `["No geometry assigned"]`, FeedVsTool → `["is far from the
  tool's"]`, DrillSize → `["drill Ø"]`.
- `RuleId::ALL` (new, `pub const ALL: [RuleId; 28]`, table order) drives the loops.
