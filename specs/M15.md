# M15 – Select, move and edit elements

Branch `feature/edit-elements`. Crates touched: `hc-geom` (shape recognition), `app`. No project format change
(`FORMAT_VERSION` unchanged: an edit only rewrites `Item::geom` with the existing `Segment` variants), no new dependency.

## User decisions (override anything below)
- **Circle: Diameter is the editable field, not Radius.** Label **Diameter** (display value `2r`; a typed `d` sets
  `r = d / 2`, validation `d > 0` with the existing "Circle needs a diameter" message). Below it a read-only **Radius**
  row (`r`) replaces the read-only **Ø** row. Update every test/doc line that edits or queries "Radius"/"Ø" for a
  circle accordingly (e.g. test 22: set **Diameter** to 16 → radius 8; in inch, **Diameter** 1.0 → radius 12.7 mm;
  test that checks "Radius absent" for non-circles checks **Diameter** absent). "Corner radius" of rectangles is unchanged.
- A plain drag starting on an element moves it (D-rule as written): confirmed.

## Scope
**In:**
- Drag canvas elements (drawn and imported, contours and DXF points) with the Select tool; the grabbed point snaps
  to the moving items' own snap points, the drop point snaps to the other items' snap points; `Shift` while dragging
  locks to horizontal / vertical; `Esc` cancels the drag. One undo step per drag.
- Properties derived from the geometry: line → X1/Y1/X2/Y2 + Length; circle → Center X/Y + Radius; axis-aligned
  rectangle → X/Y/Width/Height/Corner radius; anything else (other contour, DXF point, multi-selection) → X/Y of the
  bounding box (editing moves it). All editable fields are undoable, one step per committed edit.
- Item ids never change, so operations and their manual tabs follow.
- Docs: `drawing.md`, `interface.md`, `shortcuts.md`; one new screenshot.

**Out (explicitly):** resize/rotate handles on the canvas; arrow-key nudge (the Transform box **Move** already does
numeric dx/dy); grouping (drawn text stays one item per glyph stroke, select it with a box); editing a text's string or
font after it was added; recognising slots (rect with r = min(w,h)/2), rotated rectangles, ellipses, polygons or single
arcs; edits of individual segments/vertices; duplicate/copy; grid snap; per-op toolpath caching.

## Existing code this builds on (read before coding)
- `AppState::transform_selection` / `Project::transform_items` (move/rotate/scale/flip; the Transform box in
  `panels::transform_group` already has **Move X / Move Y / Move** = numeric move). Reused unchanged.
- `AppState::commit_undo(idle)` is called by `App::show` every frame with `idle = no pointer button down && no
  keyboard focus`. A canvas drag or a DragValue drag is therefore already one step, and a typed value one step on
  Enter/focus loss. **No new undo code**; the only rule is "restore the exact original geometry on cancel", then
  `project == undo_base` and no step is recorded.
- Manual tabs (`ManualTabs::positions`) are fractions of the contour length from its start, so they survive a
  translation unchanged; on a resize they stay at the same fraction (and `align_like` below keeps start and
  direction). Automatic tabs are recomputed anyway. Toolpaths regenerate through the whole-project compare in
  `refresh_toolpaths`.
- M13 rules in `click_select` (Shift toggles and keeps the op; a plain click on a contour of the current tab op
  changes nothing) are not changed.

## Decisions
| # | topic | decision |
|---|---|---|
| D1 | Start of a move | A primary drag (egui's own drag threshold, so a click never moves) with no `Shift` and no `Space`, whose press point is within the pick tolerance of a visible item: if that item is not selected, a plain `click_select` runs first; if the item is then in the selection, the whole selection moves. Otherwise (empty space, `Shift` held at the start, or the M13 tab-contour rule kept the old selection) the old box selection starts. Tab markers still win over everything. |
| D2 | Snapping | grab point = nearest snap candidate of the **moving** items within `SNAP_PX / zoom` of the press point, else the raw press point. Target = nearest snap candidate of the visible **non-moving** items within `SNAP_PX / zoom` of the cursor, else the raw cursor. Delta = target − grab. The snap cache is not rebuilt during the drag (its non-moving entries stay valid; the moving ones are filtered out); `end_move` rebuilds it. |
| D3 | Axis lock | `Shift` held during the drag: the smaller component of the delta becomes 0 (`|dx| >= |dy|` keeps X). |
| D4 | Cancel | `Esc` during a drag restores the original geometry and `dirty` flag; the rest of that drag does nothing. Undo/redo/new/open during a drag also end it. |
| D5 | Recognition | in `hc_geom::shapes::recognize`, tolerance `RECOGNIZE_TOL = 1e-3` mm for points/radii/axis alignment and `1e-6` rad for sweeps (rules below). Circle is checked before rectangle (a 4-quarter-arc "rectangle" with w = h = 2r is a circle). |
| D6 | Fixed point on edit | circle: the centre (its arcs keep `start_angle` and `sweep`, only `center`/`radius` change, so a two-half-arc DXF circle stays two arcs); line: the start point, Length keeps the direction; rectangle: the min (bottom-left) corner, rebuilt by `shapes::rect` then `align_like` restores the old orientation and start corner. |
| D7 | Validation | the existing `add_shape` messages (shared code): "Line is too short", "Rectangle needs a width and a height", "Corner radius must be 0 or more", "Corner radius must be at most {fmt_len(min(w,h)/2)}", "Circle needs a diameter". An invalid edit changes nothing; the field shows the old value again on the next frame. The message is shown only for a typed value (not while dragging a DragValue, to avoid one message per frame). |
| D8 | Typing | editable property fields do not apply on every key press (`DragValue::update_while_editing(false)`), so typing "0.5" never applies the intermediate "0". The draw form and the op fields keep today's behaviour. |
| D9 | Multi-selection | only the X/Y of the selection bounding box (edit = move) plus the existing Transform box. |
| D10 | Toolpaths during a drag | `App::show` skips `refresh_toolpaths` while `state.moving.is_some()` (one regeneration at the drop instead of one per frame); the old toolpaths stay drawn until then. |

## Changes (exact)

### `crates/hc-geom/src/shapes.rs`
```rust
/// Tolerance (mm) for recognising a drawn-tool shape in arbitrary (e.g. imported) geometry.
pub const RECOGNIZE_TOL: f64 = 1e-3;
const RECOGNIZE_ANG: f64 = 1e-6;

/// A contour that is exactly one of the drawing-tool shapes.
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum Primitive {
    /// `a` = segment start, `b` = segment end.
    Line { a: Point, b: Point },
    /// `min` = bbox min corner; `r` = 0 for sharp corners.
    Rect { min: Point, w: f64, h: f64, r: f64 },
    Circle { center: Point, r: f64 },
}

/// Recognises a line, circle or axis-aligned (optionally rounded) rectangle; None for anything else.
pub fn recognize(c: &Contour) -> Option<Primitive>;

/// `new` with the orientation of `old` (when both are closed and non-degenerate) and, for a closed `new`, its
/// segments rotated so it starts at the segment start nearest to `old`'s start mapped proportionally from `old`'s bbox
/// into `new`'s bbox. Keeps manual tab fractions in place when a rectangle is rebuilt.
pub fn align_like(old: &Contour, new: Contour) -> Contour;
```
`recognize` rules (`T = RECOGNIZE_TOL`, `A = RECOGNIZE_ANG`, `segs = &c.segments`; empty → None):
1. **Line**: `!c.closed && segs.len() == 1` and `segs[0]` is `Line { start, end }` → `Line { a: start, b: end }`.
   Any other open contour → None.
2. **Circle** (closed): every segment is an `Arc`; with `segs[0]`'s centre `c0`, radius `r0`, sweep sign `s0`: every arc
   has `center.distance(c0) <= T`, `|radius − r0| <= T`, `sweep.signum() == s0`; and `|Σ|sweep| − TAU| <= A * segs.len()`
   → `Circle { center: c0, r: r0 }`.
3. **Rectangle** (closed), `n = segs.len()`:
   - every `Line` is horizontal (`|Δy| <= T`) or vertical (`|Δx| <= T`), not both (length > T);
   - the lines, taken in contour order (cyclic), alternate horizontal / vertical;
   - `n == 4`: all four are lines → `r = 0`;
   - `n == 8`: kinds alternate (`segs[i]` is an arc iff `segs[(i+1) % 8]` is a line), the 4 arcs have
     `||sweep| − FRAC_PI_2| <= A`, the same sweep sign, and that sign equals `c.signed_area().signum()` (convex
     corners), radii within `T` of the first arc's → `r` = first arc's radius;
   - any other `n` → None.
   Result: `b = c.bbox()`, `Rect { min: b.min, w: b.width(), h: b.height(), r }`.

`align_like` (exact):
```rust
pub fn align_like(old: &Contour, mut new: Contour) -> Contour {
    if let Some(o) = old.orientation() {
        new.set_orientation(o);
    }
    if !new.closed || new.segments.is_empty() || old.segments.is_empty() {
        return new;
    }
    let (ob, nb) = (old.bbox(), new.bbox());
    let rel = |v: f64, lo: f64, size: f64| if size > EPS { (v - lo) / size } else { 0.0 };
    let s = old.start();
    let t = Point::new(
        nb.min.x + rel(s.x, ob.min.x, ob.width()) * nb.width(),
        nb.min.y + rel(s.y, ob.min.y, ob.height()) * nb.height(),
    );
    // first index on ties
    let k = (0..new.segments.len())
        .min_by(|&i, &j| new.segments[i].start().distance(t).total_cmp(&new.segments[j].start().distance(t)))
        .unwrap();
    new.segments.rotate_left(k);
    new
}
```
Export both through `pub mod shapes` (already public); no `lib.rs` change needed.

New functions (section "selection", after `box_select`):
```rust
/// Drag start at `p` (world): when a visible item is within `pick_tol`, applies the plain-click rules if it is not
/// selected yet, then starts moving the selection if that item is selected. False = no move (the canvas starts a box).
pub fn start_move(&mut self, p: Point, pick_tol: f64, snap_r: f64) -> bool;
/// Moves the dragged items so the grab point lands on the cursor (or the snap target near it); `axis_lock` zeroes the
/// smaller component. No-op without a drag. Ids that no longer exist are skipped.
pub fn drag_move(&mut self, cursor: Point, snap_r: f64, axis_lock: bool);
/// Finishes the drag (keeps the geometry, rebuilds bboxes and snap cache).
pub fn end_move(&mut self);
/// Restores the geometry and `dirty` from before the drag.
pub fn cancel_move(&mut self);
```
- `start_move`: `hit::pick(&items, visible, p, pick_tol)`; None → false. If `!selection.contains(hit)` →
  `self.click_select(p, pick_tol, false)`. Still not contained → false. `orig` = clones of `(id, geom)` of the
  selected items (in `project.items` order). `grab = snap::nearest(&self.snap_cache.cands, &self.project.items,
  |i| self.selection.contains(&i.id), p, snap_r).map_or(p, |s| s.p)`. `delta = (0,0)`, `snap = None`,
  `was_dirty = self.dirty`. Returns true.
- `drag_move`: target snap = `snap::nearest(cands, items, |i| self.is_visible(i) && !ids.contains(&i.id), cursor,
  snap_r)`; `d = target.map_or(cursor, |s| s.p) − grab`; axis lock per D3. For each `(id, g)` in `orig` whose item
  exists: `item.geom = g.clone()` then translated by `d` (`Contour::transformed(&Transform::translate(d.x, d.y))`,
  `Point + d`), and `self.item_bbox[index] = hit::item_bbox(item)`. Store `delta = d`, `snap`. `self.dirty = was_dirty
  || d != Point::new(0.0, 0.0)`. Do **not** call `items_changed` here.
- `end_move`: `self.moving = None; self.items_changed();`
- `cancel_move`: if a drag is active, write every `orig` geometry back, `dirty = was_dirty`, `moving = None`,
  `items_changed()`.
- `escape()`: new first branch `if self.moving.is_some() { self.cancel_move(); }` (then return; the other branches
  become `else if`). Doc: "Escape: cancels a move drag, else drops a pending first point, …".
- `set_tool()`: call `self.end_move()` first when `moving.is_some()`.

## Risks
- A plain drag that starts on an item now moves it instead of starting a box (D1). On dense DXFs a box must start on
  empty space or use `Shift` (additive). Undo fixes accidents. Documented.
- Recognition tolerance 1e-3 mm: a DXF rectangle with endpoints off by more is shown as "other" (still movable); an
  edit snaps a recognised one exactly axis-aligned (≤ 1 µm change). Accepted.
- Rect rebuild via `align_like` keeps orientation and the start corner approximately; manual tab fractions then sit at
  the same relative place, not the same absolute mm. Accepted for a hobby tool.
- DragValue dragging of Radius/Width rebuilds the snap cache and regenerates toolpaths every frame (D10 only covers
  canvas drags); fine for hobby-size projects, same as today's op fields.
- kittest drag simulation (test 19–21) is new in this repo; if `drag_at`/`drop_at` behave differently than assumed,
  the state tests remain the source of truth.
