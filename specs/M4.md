# M4 – GUI shell (`app`)

## Scope
**In:** menus, layer panel, operations panel (create/edit/reorder/delete, no toolpaths), properties panel, canvas (pan/zoom/fit, grid, origin, stock, geometry), selection (click, shift-click, window/crossing box, Esc), tool library dialog, file I/O with unsaved-changes guard, message panel, CLI file argument, units switch.
**Out:** drawing/editing/deleting geometry (M10), toolpaths and their preview (M5), tabs UI (M6), simulation (M9), undo/redo, saving layer visibility, G-code export (M7).
**Look (req. 10):** our own plain egui look: text menus, default egui theme (follows the OS light/dark mode), no copied icons, colours or panel arrangement from estlCAM.

## Dependencies (app crate)
`eframe = "0.37"` (already present), `hc-geom`, `hc-dxf`, `hc-project` (path), `rfd = "0.17"` (0.17.2, MIT).
rfd uses native dialogs: NSOpenPanel on macOS and IFileDialog (COM) on Windows, both OS built-ins with no extra install. The default features (xdg-portal, D-Bus over pure Rust) only matter on Linux CI, which only builds and tests.
Use the **synchronous** `rfd::FileDialog`; blocking the UI thread while a dialog is open is fine.
Dev-dep: `egui_kittest = "0.37"` (MIT/Apache) **without** the `wgpu`/`snapshot` features. It does headless logic and accessibility-tree tests only. If it does not build cleanly against 0.37 in under an hour of effort, drop it and the K tests below.

## Modules (`app/src`)
| module | content | egui use |
|---|---|---|
| `main.rs` | eframe setup, CLI arg, `App::ui` → `self.show(ui)` | yes |
| `state.rs` | `AppState`: project, path, dirty, library (+ load error), selection, selected op, hidden layers, messages, view | no |
| `view.rs` | `View` math + `grid_step` | `Pos2/Vec2/Rect` only |
| `hit.rs` | `dist_to_segment`, `pick`, `box_select`, `tessellate_arc` | `Pos2/Rect` only |
| `aci.rs` | `aci_rgb(index, dark) -> Color32` | `Color32` only |
| `canvas.rs`, `panels.rs`, `tool_dialog.rs` | painting, input, widgets | yes |

The pure modules use only egui's plain data types (no `Context`/`Ui`) and have unit tests.
**All edits go through `AppState` methods** (`import_dxf`, `open`, `save`, `new_operation`, `move_op`, …), which set `dirty = true`. The UI code holds no project logic.

## View math (`view.rs`)
`View { zoom: f32 /* px per mm */, offset: Vec2 /* screen position of world (0,0) relative to the canvas rect min */ }`, with the Y axis flipped:
`sx = rect.min.x + offset.x + wx·zoom`, `sy = rect.min.y + offset.y − wy·zoom`. Compute in f64 internally and expose f32 screen points.
- `world_to_screen(rect, Point) -> Pos2`, `screen_to_world(rect, Pos2) -> Point`.
- `zoom_at(rect, screen: Pos2, factor)`: the world point under `screen` stays fixed. Zoom is clamped to [0.001, 10 000] px/mm.
- `fit(rect, bbox: &BBox, margin_px = 20)`: zoom = min((w−2m)/bw, (h−2m)/bh), and the bbox centre goes to the rect centre. If the bbox is empty, use the stock rect. If the bbox has zero width or height, use its other dimension (or 1 mm).
- `grid_step(zoom, units, min_px = 15) -> f64` (mm): the smallest step from {1,2,5}·10^k **in display units** (mm, or inch × 25.4) whose screen size is ≥ min_px. Draw a light line at each step and a stronger one every 10th step, plus the X/Y axes in red/green through the origin.

## Canvas
- Paint order: grid → stock rect (dashed, grey) → origin marker (two 20 px arrows, X red, Y green) → items of visible layers in layer colour → selected items (orange, 2.5 px) → selection box.
- Contours are drawn with `Shape::line` (open) or `Shape::closed_line`. Arcs use `tessellate_arc(center, r, start, sweep, tol_world)` with `tol_world = 0.25 px / zoom` and n = clamp(ceil(|sweep| / (2·acos(1 − tol/r))), 1, 512). Points are drawn as small crosses.
- Input: middle drag, or Space + left drag → pan. A `MouseWheel` event with unit `Line` (a mouse wheel) → zoom at the cursor (factor 1.2 per notch). Unit `Point` (a trackpad two-finger scroll) → pan. `zoom_delta()` (pinch, or Ctrl/Cmd + wheel) → zoom at the cursor. Keys (only when the canvas is hovered and no text field has focus): `F` fit, `Esc` clear the selection.
- After import and open, fit the view to the bbox of all items.
- **Performance (~10k segments):** `AppState` keeps an `item_bbox: Vec<BBox>` cache, rebuilt whenever items change. Culling skips items whose bbox misses the visible world rect, and an item whose screen bbox is under 2 px is drawn as one dot. egui repaints only on input, which is enough. No spatial index (shortcut: add a grid index if picking gets slow above ~50k segments).

## Selection (`hit.rs`)
- `dist_to_segment(p, seg)`: line → distance to the clamped projection. Arc → if p's angle lies inside the sweep (either sign), `| |p−c| − r |`, otherwise the distance to the nearer endpoint. Points → Euclidean distance.
- `pick(items, visible, p_world, tol_world) -> Option<u64>`: the nearest item within `tol_world = 6 px / zoom` among visible layers. On a tie (|Δ| < 1e-9) the item drawn last (later in `items`) wins.
- Click: replace the selection with the picked item (empty if none). Shift + click toggles it. A drag of more than 4 px with the left button is a box: dragged to the right (end.x ≥ start.x) it is a **window** (item bbox fully inside), drawn as a solid blue box. Dragged to the left it is a **crossing** (fully inside, or any tessellated piece intersects the box; a bbox overlap alone is **not** enough), drawn as a dashed green box. Shift + box adds to the selection.
- Hidden layers are neither drawn nor picked nor boxed. Hiding a layer removes its items from the selection.

## Panels
- **Menu:** File: New, Open project…, Save, Save as…, Import DXF…, Quit. View: Zoom to fit. Settings: Units ▸ mm / inch (stored in `project.units`), Tool library…. Shortcuts: Cmd/Ctrl + N, O, S, Shift+S, I; F fit.
- **Left panel, Layers:** one row per `project.layers` entry: visibility checkbox, colour swatch, name and item count.
- **Left panel, Operations:** a list in execution order showing an enabled checkbox, the name, the kind and `T<n>`, with buttons ▲ ▼ ✕. Clicking a row makes it the selected operation **and** sets the canvas selection to its items. A "New operation" button (disabled when the selection is empty) opens an inline form: kind (Engrave / Contour / Pocket / Drill) and tool (embedded project tools ∪ library tools; the project copy is listed for ids it has). Create calls `Project::add_operation` with name `"<Kind> <n>"`.
- **Right panel, Properties:**
  - Operation selected: name, enabled, tool combo, and kind parameters (side, direction, stepover %, peck on/off + value).
  - It also shows depth, depth/pass, feed, plunge feed and rpm, plus an "Apply tool defaults" button and a "Use current selection" button (op.items = selection).
  - Otherwise, with a selection: the count; for a single item its layer, open/closed, segment count, length, bbox W×H, and Ø for a circle. All read-only.
- **Length/feed fields:** `DragValue` on the display value (`to_display`) with `.custom_parser(|s| parse_length(s, units).map(|mm| to_display(mm, units)))` and a unit suffix (`mm`, `in`, `mm/min`, `in/min`). It writes back `from_display`. This one helper is used everywhere, including the tool dialog.
- **Status bar:** cursor `X 12.345 Y 6.789 mm` (3 decimals for mm, 4 for inch), zoom in %, where 100% means 1 px per mm, and the selection count.
- **Message panel:** a top panel shown while messages exist. Each message has a severity, text and an ✕. It shows DXF warnings (with a readable text per `ImportWarning` variant), ignored counts (`Ignored: 6 DIMENSION, 4 HATCH…`), project `Problem`s and I/O errors, using the error's `Display` text.
- **Window title:** `HobbyCAM – <file name or "untitled">` followed by `*` when dirty.

## Files, dialogs, guard
- **Open project** (`.hcam`) replaces the project. **Import DXF** appends to the current project (`add_dxf`, using the file name). **Save** goes to the current path, and **Save as** is used if there is none. A failed save leaves `dirty` set and shows a message.
- **Unsaved changes guard:** on New, Open or Quit while dirty, an `egui::Modal` asks "Save changes?" with Save / Discard / Cancel. For Quit (menu or window close): on `viewport().close_requested()` while dirty, send `ViewportCommand::CancelClose` and show the modal.
- **Tool library:** loaded at startup from `default_library_path()`.
  - On a load **error**, the library window shows the error and a button "Start a new empty library". The old file survives as `tools.json.bak` on the next save. Until then, Save is disabled.
  - The window lists the tools; Add (id = `next_free_id`) / Edit / Delete; the form covers every `Tool` field, with lengths via the helper.
  - Save writes the library and creates its directory if missing (`create_dir_all`). Edits to library tools do not change the tools already embedded in the project.
- **CLI:** `hobbycam [file]`. A path ending in `.dxf` (case-insensitive) starts a new project, imports it and fits the view. `.hcam` opens it. Anything else → an error message shown in the app; the app still starts.

## Risks
- The `MouseWheel` unit (Line vs Point) depends on the platform/winit. If a Windows precision touchpad reports `Line`, it zooms instead of panning; that is acceptable.
- A blocking rfd dialog on macOS must run on the main thread. eframe's `ui` already does, so never call it from a spawned thread.
- Layer visibility is not saved (adding it would bump the format). Revisit with M10.
- egui text fields inside `DragValue` with a custom parser: if parse fails, the value stays unchanged and there is no red error state. That is acceptable for v1.

**Rulings on the coder's points**
(a) `delete_op` with an unknown id sets dirty: accepted. The UI can't trigger it.
(b) f32 `View.offset` drift: accepted for hobby scale.
(c) `select_op` puts hidden-layer items into the selection: accepted, and it is the correct behaviour. An operation's items do not depend
    on layer visibility, so "Use current selection" must not silently drop them.
(d) The 512-piece cap and per-frame tessellation: accepted. At r = 1 m and 100 px/mm the worst visible sagitta is ≈ 2 px. Cache the
    tessellation only if the 10k-segment profile shows it (later).
(f) Auto-fit the stock on import: later, **moved to M5**. On import, when the stock still equals the default and the
    project has no operations, set the stock XY to the items' bbox (thickness unchanged). The stock starts to matter in M5/M8.
