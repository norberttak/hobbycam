# M10 – Drawing tools and work origin

M10 is split. **M10a first** (snap engine, set origin, line/rectangle/circle, numeric input, transforms, delete, the shared-edge test),
then **M10b** (text: Hershey single-line + TTF outline). M10b reuses the M10a tool modes, form and snap engine and adds one new crate,
so it can be reviewed and signed off on its own. Each part ends green (fmt, clippy, test) with a user sign-off.

## Scope
**In (M10a):**
- Undo/redo of every project edit (user decision, 2026-10-27).
- Snap engine (`app/src/snap.rs`): segment ends, contour corners, arc/circle centres, drill points; used by every canvas tool.
- **Set origin tool** (new user requirement): hover snaps to a candidate with a marker and a kind label, click makes that point the
  work origin, Escape cancels. Stored as a new `WorkOrigin::Point`. The presets (drawing origin, stock bottom left, stock center) stay.
- Settings → Stock submenu: stock position, size, thickness and the origin choice incl. numeric X/Y of a picked point. There is no stock
  UI today, so without it a picked origin could never be switched back to a preset.
- Line, rectangle (corner radius 0 = sharp), circle: two canvas clicks (snapped) or exact numbers in a form.
- Move / rotate / scale / mirror the selection (numeric), delete the selection.
- M5 ruling (e): tests for an island that shares whole edges with its boundary.

**In (M10b):** new crate `hc-text`; Text tool: single-line Hershey (open strokes, for engraving) and TTF outline (closed contours,
for pockets/contours) with the bundled Ubuntu Light font.

**Out:** editing a drawn shape's parameters after creation (shapes and text
become plain contours), polylines/arcs/ellipses as drawing tools, graphical (drag) move/rotate, copy/duplicate/array, non-uniform scale
(arcs would become ellipses), snap to midpoints/intersections/grid/stock corners, ortho/angle constraints, multi-line text, alignment,
kerning, letter spacing, text on a path, user-supplied or system fonts, an origin that follows geometry when the geometry is moved later.

## Decisions
- **Origin storage: `WorkOrigin::Point(Point)` (drawing coordinates, mm) and format v4.** The existing enum holds only presets. An extra
  optional field with `serde(default)` would avoid the bump, but a v3 app would then load a v4 file, silently ignore the point and emit
  G-code relative to the wrong zero; that is a crashed bit, so old apps must refuse the file (same rule as the `Geom` comment). JSON:
  `"origin": {"point": {"x": 10.0, "y": 5.0}}`; presets stay strings (`"stock_center"` …). `migrate` for `found < 4` is the identity.
  `WorkOrigin` keeps `Copy`, drops `Eq` (f64). v1–v3 fixtures are not touched and still load. The picked point does not follow the
  geometry if it is moved afterwards (it is a machine setting, not an attribute of an item); M11 documents "set the origin last".
- **Everything else stays in drawing coordinates.** Canvas, numeric fields, selection properties and the sim use drawing coordinates;
  only `hc_post::export` shifts (unchanged mechanism, one new arm in `work_origin`). So the sanity checks stay correct for any origin:
  `OutsideStock` compares toolpath and stock both in drawing coordinates, and `generate`/`simulate` never see the origin. The status bar
  adds `· Work X … Y …` (relative to the work origin) when `work_origin != (0,0)`, to compare with the LinuxCNC DRO.
- **G-code header:** `(Units: mm. Z0 = top of stock. XY0 = drawing point X10 Y5)`, the numbers via `fmt_num(to_display(v), decimals)`
  of the job (3 mm / 4 inch). Comment text stays sanitised; no parentheses inside. The "set Z0" line is unchanged (the user re-zeroes Z
  per tool; XY stays).
- **Undo/redo: whole-`Project` snapshots, depth `UNDO_DEPTH = 100`.** One generic commit point catches every edit (drawing,
  transforms, delete, origin, stock, machine, units, ops, tabs, DXF import) without touching each mutation site. `AppState` keeps
  `undo: Vec<Project>`, `redo: Vec<Project>`, `undo_base: Project` (the last committed state) and `saved: Project` (the state on disk).
  `commit_undo(idle)` runs at the end of `App::show` with `idle = no pointer button down && !ctx.egui_wants_keyboard_input()`: if idle
  and `project != undo_base`, push `undo_base` (drop the oldest beyond 100), `undo_base = project.clone()`, clear `redo`. So a drag
  (tab, slider) or typing in a field is one step, committed on release / focus loss. `undo()` first commits a pending change, then pops
  into `project` (current pushed to `redo`); `redo()` the reverse; both set `undo_base = project`, call `items_changed()`, drop
  `selected_tab`, keep `selected_op` only if the op still exists, and set `dirty = project != saved` (back to the saved state = clean;
  one compare, the same cost as `refresh_toolpaths`). Save sets `saved`; new/open (`replace_project`) clears both stacks and sets
  `undo_base = saved = project`. Selection, view, layer visibility, sim and the tool library (its own file) are not in `Project` and
  are never snapshotted. Shortcuts: Cmd/Ctrl+Z undo; Cmd/Ctrl+Shift+Z and Ctrl+Y redo (consumed in `panels::shortcuts`, Shift+Z first,
  and only when no text field has focus, so a focused TextEdit keeps its own undo). `Edit` menu (between File and View): `Undo`,
  `Redo` with `shortcut_text`, disabled when the stack is empty (the text is the accessible name).
- **Snap rules:** radius `SNAP_PX = 10.0` screen px (selection uses 6 px; snapping should grab earlier), converted with `/ zoom`.
  Candidates per item (hidden layers excluded):
  - Contour that `as_circle()` → only its `Center`.
  - Other contours: each segment start is a `Corner`, except the start of an open contour, which is an `End`; the end of the last
    segment of an open contour is an `End`. Every `Arc` segment adds its `Center`. Duplicates (same kind, within 1e-9 mm) in one item
    are dropped (a circle drawn as two half arcs gives one Center).
  - `Geom::Point` → `Point` (drill points).

  The nearest candidate wins (world distance). Exact ties (≤ 1e-9 mm) take the kind order End, Corner, Point, Center. Ties only decide
  the label: coincident candidates give the same coordinate. Candidates are cached in `items_changed()` (one pass, O(segments)), not
  rebuilt per frame.
- **Snap use:** Set origin requires a snap (a click with no candidate does nothing; the hint stays). Drawing tools use the snap when
  there is one, else the raw cursor point.
- **Tool model:** one active `CanvasTool` (Select default). In non-Select tools a primary click is a tool click (no selection, no box,
  no tab editing); pan and zoom work as before. Escape: clears a pending first point, else returns to Select. Set origin is one-shot
  (back to Select after a successful pick); drawing tools stay active so several shapes can be drawn in a row.
- **Form = numeric input.** Each drawing tool has a form in the right panel (it replaces the selection/op properties while the tool is
  active). Canvas clicks write into the form fields and the second click (first for Text) adds the shape from the form; `Add` adds it
  from typed numbers. Form values persist between shapes. Lengths use `length_field` (project units).
- **Shapes** are plain closed/open `Contour`s, `Source::Drawn`, on layer `Drawing` (ACI 7, created on first use). Rectangle: CCW,
  starting at (min.x + r, min.y), edges and quarter arcs; zero-length edges (r = half the side) are omitted. New items become the
  selection. No auto-fit of the stock for drawn items (the stock menu does that by hand).
- **Transforms** act on the selection about the selection bbox centre (rotate, scale, flip) or by dX/dY (move). Angle in degrees, CCW
  positive. Scale factor finite and > 0, uniform. Manual tab positions are fractions along the stored direction, which a transform
  keeps, so they stay on the same physical spot of the part. The origin does not move.
- **Delete:** Delete/Backspace on the canvas deletes the selected tab if there is one (as now), else the selected items
  (`Project::remove_item`, which also drops op references and manual tabs). Also a `Delete` button. An op left without items shows
  the existing NoItems error.
- **Shortcuts** (canvas hovered, no text focus, like `F`): `L` line, `R` rectangle, `C` circle, `T` text (M10b), `O` set origin,
  Escape as above. A `Draw` menu between View and Settings lists the same entries with `shortcut_text`.
- `fit_stock_to_items`: the "untouched" compare ignores `stock.origin` (setting a preset before the first import must not stop the
  auto-fit). One line.
- **Text (M10b):** `height` = cap height (the height of `H`), measured from the font's own `H` glyph so both fonts honour it exactly.
  `at` = baseline start of the first glyph. Advance widths only (no kerning). Characters not in the font are skipped with their
  advance = the space width and are reported; the app shows a Warning `Not in the font: é` and still adds the rest. TTF quadratic and
  cubic curves are flattened to lines with `tol = 0.01 mm` (PLAN default), using Wang's formula. Hershey strokes are always
  `closed: false`, also when a stroke ends at its start (`O`): a stroke font is for Engrave only, and Pocket on it gives the existing
  OpenContour error.

/// Open, one Line. None if a or b is non-finite or |b − a| < EPS.
pub fn line(a: Point, b: Point) -> Option<Contour>;
/// Closed, CCW, start (min.x + r, min.y). None if non-finite, w or h < EPS, r < 0, or r > min(w, h)/2 + EPS (r is then clamped to

### app state (M10a; the `Text` variants and the text fields of `DrawForm` are added in M10b)
```rust
pub enum CanvasTool { Select, SetOrigin, Line, Rect, Circle, Text }
pub enum Shape { Line { a: Point, b: Point }, Rect { min: Point, w: f64, h: f64, r: f64 }, Circle { c: Point, r: f64 },
    Text { at: Point, text: String, font: hc_text::Font, height: f64 } }
/// Persistent form values (mm). Defaults: zeros, w = h = 20, r = 0, d = 10, text "HobbyCAM", Hershey, height 10.
pub struct DrawForm { pub a: Point, pub b: Point, pub w: f64, pub h: f64, pub r: f64, pub d: f64,
    pub text: String, pub font: hc_text::Font, pub height: f64 }
pub struct XformForm { pub dx: f64, pub dy: f64, pub angle_deg: f64, pub factor: f64 } // defaults 0, 0, 90, 2
// AppState fields: tool: CanvasTool, draw: DrawForm, xform: XformForm, pending: Option<Point>,
//                  snap_cache: Vec<(usize, Point, SnapKind)>  (rebuilt in items_changed)
impl AppState {
    pub fn set_tool(&mut self, t: CanvasTool);            // clears `pending`
    pub fn escape(&mut self);                             // pending → None, else tool → Select (keeps the old clear-selection)
    pub fn snap_at(&self, p: Point, radius: f64) -> Option<Snap>;
    /// `p` is already snapped. SetOrigin: needs `snapped`; Line/Rect/Circle: first click → pending + form a, second → form + add_shape;
    /// Text: add at p.
    pub fn canvas_click(&mut self, p: Point, snapped: bool);
    /// Validates, adds via add_drawn, selection = new ids, dirty. Err = user message (also pushed as a Warning by canvas_click).
    pub fn add_shape(&mut self, s: Shape) -> Result<Vec<u64>, String>;
    pub fn set_origin(&mut self, o: WorkOrigin);          // dirty only on change
    pub fn set_stock(&mut self, s: Stock);                // dirty only on change, like set_machine
    pub fn selection_bbox(&self) -> BBox;
    pub fn transform_selection(&mut self, t: &Transform); // no-op on empty selection; items_changed; dirty
    pub fn delete_selection(&mut self);                   // remove_item each, selection cleared, dirty
    pub fn commit_undo(&mut self, idle: bool);            // see Decisions
    pub fn undo(&mut self) -> bool;                       // false when nothing to undo
    pub fn redo(&mut self) -> bool;
    pub fn can_undo(&self) -> bool;
    pub fn can_redo(&self) -> bool;
}
pub const UNDO_DEPTH: usize = 100;
```
Rect from two clicks: min = component-wise min, w/h = |Δ|. Circle from two clicks: r = |rim − centre|. Errors (exact texts):
`Line is too short`, `Rectangle needs a width and a height`, `Corner radius must be at most 5.000 mm` (fmt_len of min/2),
`Circle needs a diameter`, `Text needs a height` (M10b).

### hc-text (M10b)
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Font { /// Roman Simplex, open strokes.
    Hershey, /// Ubuntu Light, closed outlines.
    Outline }
#[derive(Debug, Clone, PartialEq, Default)]
pub struct TextGeom { pub contours: Vec<Contour>, /// In text order, without duplicates.
    pub missing: Vec<char> }
#[derive(Debug, Clone, PartialEq)]
pub enum TextError { BadHeight } // Display: "Text height must be greater than 0"
pub const FLATTEN_TOL: f64 = 0.01;
/// One line (a '\n' counts as missing). Deterministic; the font is parsed once (OnceLock).
pub fn text(s: &str, font: Font, height: f64, at: Point) -> Result<TextGeom, TextError>;
```
Internals (tested, `pub(crate)`): JHF parser (per glyph: cols 0–4 number, 5–7 vertex count incl. the bounds pair, then char pairs,
value = char − 'R', `" R"` = pen up; a glyph may continue on following lines until 2·count characters are read; glyph k ↔ ASCII 32+k;
Y is down in the file, flip it); `flatten_quad` / `flatten_cubic` with n = ⌈√(M/(4·tol))⌉ / ⌈√(3M/(4·tol))⌉, M = the largest second
difference of the control points (Wang), n clamped to 1..=64.

## Acceptance tests
**M10a** (hc-geom `shapes` unit tests unless noted; tolerances 1e-9 mm)
1. `line((0,0),(3,4))` → open, 1 Line, length 5. Zero length, NaN → None.
2. `rect((10,20), 30, 10, 0)` → closed, 4 Lines, Ccw, start (10,20), bbox (10,20)–(40,30), area 300, length 80.
   `r = 2` → 8 segments (lines/arcs alternating, arcs sweep +π/2), start (12,20), same bbox, length 64 + 4π, area 300 − (4 − π)·4,
   each segment starts where the previous ends. `r = 5` → 6 segments (no zero-length sides). `rect(min, 10, 10, 5)` → 4 arcs, area 25π.
   `r = 5.0001`, `r = −1`, `w = 0`, NaN → None.
3. `circle((1,2), 2.5)` → `as_circle()` = Some(radius 2.5, centre (1,2)); r 0 → None.
4. `Project::add_drawn` (hc-project): two geoms into a new project → layer `Drawing` color 7 added once (a second call adds no layer),
   ids 1, 2, `Source::Drawn`, `next_id` 3.
5. `transform_items`: translate (5,−3) moves a rect and a Point item; rotate 90° about (0,0) maps line (1,0)–(2,0) to (0,1)–(0,2);
   scale 2 about a Ø5 circle's centre → Ø10, same centre; mirror_y(0) makes a Ccw rect Cw with the mirrored bbox; an item with manual
   tabs [0.25] keeps [0.25] and its tab point (`point_at(0.25·len)`) is the mirrored old one; unknown id ignored; other items equal.

## Risks
- **Undo memory:** 100 full snapshots; a large DXF project (a few MB in memory) can use a few hundred MB. Acceptable for hobby files;
  shortcut upgrade: lower the depth or share unchanged items via `Arc` if it bites.
- **Edits outside `App::show`** (tests, CLI open) are only committed when `commit_undo` runs; open/new reset the base, so nothing leaks.
- **Picked origin and later edits**: moving the part after picking leaves the origin at the old place. The arrows show it; M11 says
  "set the origin last".
- **Snap cache staleness**: every item mutation must go through `items_changed()` (draw, transform, delete, import, open). Tests 12–13
  cover it.
- **Shortcut letters** could fire while typing if focus detection fails; they are guarded like `F` (`egui_wants_keyboard_input`).
- **TTF text size**: flattened glyphs give many short lines (~100 per letter); pockets on long texts regenerate slower. Acceptable.
- **Hershey file format variants** (wrapped lines, numbering): handled by the count-driven parser (test 24).
- **Shared-edge pocket** may expose a cavalier limitation (test 15); then it becomes a known limitation with the SharedEdge warning.

**Tester findings**
1. Pocket cuts through islands that touch the boundary (HIGH): **must-fix**, in `hc_toolpath::offset::pocket_rings`. Rule: before
   building the `Shape`, every island that comes within the tool radius r of the boundary or of another island is shrunk by
   `ISLAND_CLEARANCE = 5e-4` mm with `offset_closed(island, -ISLAND_CLEARANCE)` (a single-polyline offset, which is robust; all
   resulting pieces are kept, an island that vanishes is dropped). "Comes within r": a sample of the island (segment ends plus points
   every ≤ r/2 along each segment) has `distance_to` ≤ r for the boundary or another island; with that spacing a real contact always
   samples ≤ r/4, so no contact is missed. Islands farther away are untouched, so existing goldens stay byte-equal. Effect: every gap
   becomes ≥ 5e-4 mm (the tester measured gaps ≥ 1e-4 as safe), the island loses at most 0.5 µm, which is below machine resolution,
   and a gap narrower than the tool is never entered anyway. Boolean subtraction was rejected: cavalier's boolean ops share the same
   coincident-edge degeneracy and would add a code path. Un-ignore `m10_shared_edge.rs:174,188,210,220,230,241` and `check.rs:665`
   (m10_15); the gouge check samples along moves every 0.05 mm against the tool edge (the tester's helper), not only end points. Add one
   case: two islands sharing an edge with each other inside the boundary → no gouge.
2. SharedEdge misses vertex and near-touching contacts (HIGH): **no detection change.** With fix 1 a touching island is no longer a
   gouge, so rule 26 becomes advisory. It stays a Warning with the midpoint test, but its message becomes `The {a} touches the {b}:
   the pocket treats them as one wall` (update `check.rs:497` and the expectation at `tests/check.rs:570`). The three `net_*` tests
   (`m10_shared_edge.rs:284,299,307`) assert `gouge ≤ OK || warned`, so they pass after fix 1: un-ignore them unchanged.
3. `transform_selection` accepts a degenerate transform (MEDIUM): **must-fix** at `app/src/state.rs:835`: no-op (not dirty) unless all six
   coefficients are finite and `|det| > 1e-12`. Un-ignore `m10_verify.rs:440`.
4. Negative/NaN corner radius message (LOW): **fix** at `app/src/state.rs:806`: `!(r >= 0.0)` → Err `Corner radius must be 0 or more`
   before the max check. Un-ignore `m10_verify.rs:294`.
5. JSON error context lost through `serde_json::Value` (LOW): **accept**, pre-existing since M3 (`from_versioned_json`), not M10
   scope. Revisit if users report confusing load errors.
