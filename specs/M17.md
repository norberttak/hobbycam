# M17 – Tool schematics

Branch `feature/tool-schematics` (from `main`, M13–M16 merged). Crate touched: `app` only. No project or library format
change, no new dependency (egui `Painter` only, no images).

## Scope
**In:**
- New module `app/src/tool_sketch.rs`: a pure geometry function `sketch(&Tool, Units) -> Sketch` (points, polylines,
  labels in a fixed 240 × 300 point box, no egui types) and a thin `paint(ui, &Sketch)`.
- `app/src/tool_dialog.rs`: the sketch is shown **to the right of the edit form** while a tool is being edited
  (Edit or Add), redrawn every frame from the edited copy, so it follows every keystroke / drag and Type change.
- Unit tests for the geometry, one kittest, `docs/src/tools.md` paragraph + regenerated `tool-library.png`, CHANGELOG line.

**Out (explicitly):** proportional / to-scale drawing; shank diameter or overall length (no such `Tool` fields);
corner-radius bits, compression / O-flute types, a real helix; drawing feed, plunge feed, RPM, depth/pass, stepover
or comment; a sketch in the tool list rows or in the operation Properties; hover / click interaction on the sketch;
new form validation (ranges stay as they are); a separate dark-mode screenshot; a 118° field for drills.

## Existing code (read before coding)
- `tool_dialog::body` draws the list grid, **Add**, then (only when `d.edit` is `Some((t, is_new))`) a separator, the
  `tool_form` grid (13 rows: Number, Name, Type, [V angle], Diameter, Flute length, Flutes, Feed, Plunge feed, RPM,
  Depth/pass, Stepover, Comment) and the OK / Cancel row. The window has `.default_width(480.0)`. There is no list
  selection: "the selected tool" is the tool in the form. Library empty, or no tool in the form: no form, **no sketch**.
- Geometric `Tool` fields: `kind` (`VBit { angle_deg }`), `diameter`, `flute_length`, `flutes`. Form ranges:
  `flutes` 1..=12, `angle_deg` 1..=179; `diameter` / `flute_length` go through `panels::length_field` with **no range**
  (0 or negative can be typed). A JSON library edited by hand can hold anything (`flutes = 0`, NaN is rejected by serde).
- `hc_project::fmt_len(mm, units)` → `"3.175 mm"` / `"0.1250 in"` (the list already uses it for "Ø …").
- Accessible label on a painted widget: `r.widget_info(|| egui::WidgetInfo::labeled(egui::Role::…, true, text))`
  (see `panels.rs` ~line 108).

## Decisions
1. **Fixed generic shape, true numbers in the labels** (not proportional). Diameters span 0.1–25 mm and flute lengths
   0–250+ mm; a to-scale drawing is either a hairline or a stub, and a clamped aspect ratio lies anyway. Hobby users
   need to see *which number is which*, so every kind uses the same body (shank + flute zone, same width) and the
   dimension labels carry the values. Two things do follow the values because they are readable at any value:
   the **V angle** (drawn angle = `angle_deg` clamped to 30°–150°, label shows the true value) and the **number of
   flute hint lines** (`min(flutes, 6)`).
2. **Beside the form**, not above: the form is ~300 pt high and ~380 pt wide; a 240 × 300 sketch beside it keeps the
   window height unchanged (the list can grow) and the window ~640 pt wide, which fits 1280 × 800.
3. **Label text = form label text + value**: `Diameter 3.175 mm`, `Flute length 12.000 mm`, `Flutes 2`,
   `V angle 60°` (the V angle and Flute length labels break after the name, see Lines 4 and 6). Units follow `project.units` via `fmt_len`.
4. **Invalid values do not change the shape**; the label shows the stored value and is painted in
   `visuals.error_fg_color`: diameter or flute length `<= 0` or not finite, flutes `== 0`. (Range checks for tools are
   still done at operation level by `hc_toolpath`; M17 adds no validation.)
5. **Drill**: there is no angle field, so the point is drawn with a fixed 118° and gets **no** angle label.
6. Colours only from `ui.visuals()` (works in light and dark): body fill `widgets.inactive.bg_fill`, outline
   `widgets.noninteractive.fg_stroke.color` 1.5 pt, hint lines `weak_text_color()` 1 pt, dimension lines / arrows /
   labels `text_color()` 1 pt, bad labels `error_fg_color`. Text `egui::FontId::proportional(12.0)`.
7. The whole outline is **one convex polygon** (shank and cutter share the width), so egui can fill it with
   `Shape::convex_polygon` and no tessellation tricks are needed.

## API (`app/src/tool_sketch.rs`, add `mod tool_sketch;` in `main.rs`)

```rust
//! Schematic drawing of a tool for the tool library form (generic shape, true values in the labels).
use hc_project::{fmt_len, Tool, ToolKind, Units};

pub const SKETCH_W: f32 = 240.0;
pub const SKETCH_H: f32 = 300.0;
pub const MAX_FLUTE_LINES: u32 = 6;
pub const V_DRAW_MIN: f64 = 30.0;
pub const V_DRAW_MAX: f64 = 150.0;
pub const DRILL_POINT_DEG: f64 = 118.0;

/// Points in the sketch box: x right, y **down**, (0,0) top left, SKETCH_W × SKETCH_H.
pub type P = [f32; 2];

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Pen { Outline, Hint, Dim }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Field { Diameter, FluteLength, Flutes, VAngle }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Anchor { LeftCenter, RightCenter, CenterCenter }

#[derive(Debug, Clone, PartialEq)]
pub struct Label { pub field: Field, pub pos: P, pub anchor: Anchor, pub text: String, pub bad: bool }

#[derive(Debug, Clone, PartialEq)]
pub struct Sketch {
    /// Tool outline, convex, clockwise or counter-clockwise, not repeated first point.
    pub body: Vec<P>,
    /// Open polylines (an arc is pre-sampled).
    pub lines: Vec<(Pen, Vec<P>)>,
    /// Filled arrow heads (triangles), Pen::Dim colour.
    pub arrows: Vec<[P; 3]>,
    pub labels: Vec<Label>,
}

pub fn sketch(t: &Tool, units: Units) -> Sketch;

impl Sketch {
    /// One-line text for accessibility / tests: "Tool sketch: " + label texts ('\n' → ' ') joined by ", ".
    pub fn summary(&self) -> String;
}

/// Allocates SKETCH_W × SKETCH_H with Sense::hover, paints, sets widget_info(Role::Image, summary()).
pub fn paint(ui: &mut egui::Ui, s: &Sketch) -> egui::Response;
```

## Exact geometry (box 240 × 300, y down)
Constants: axis `X = 90`, cutter left `L = 60`, right `R = 120` (half width `h = 30`), body top `TOP = 20`,
flute zone top `FT = 90`, tip `TIP = 240`.

`side_end` (y where the straight sides stop) and `body` per kind:
| Kind | side_end | body (in order) |
|---|---|---|
| FlatEndMill | `TIP` | (L,TOP) (R,TOP) (R,TIP) (L,TIP) |
| BallEndMill | `TIP − h` = 210 | (L,TOP) (R,TOP), then the lower half circle centre (X,210) radius h, screen angle 0 to π (y down, so π/2 is (X,TIP)), **16 segments = 17 points** from (R,210) to (L,210) — 19 points in total |
| VBit | `TIP − h / tan(a/2)`, `a = angle_deg.clamp(30,150)` | (L,TOP) (R,TOP) (R,side_end) (X,TIP) (L,side_end) |
| Drill | same as VBit with `a = 118` | same as VBit |

At a = 30 the V is 112 pt high (side_end = 128 > FT): the V always stays below the flute zone top.

Lines (`lines`, in this order):
1. `Outline`: shank / flute boundary `(L,FT)–(R,FT)`.
2. `Hint` flute lines, `n = min(flutes, MAX_FLUTE_LINES)` lines (0 lines if `flutes == 0`), in the straight zone
   `FT..side_end`: `zh = side_end − FT`, `slant = min(12, zh / 3)`, for `k in 1..=n`:
   `y = FT + slant/2 + k·(zh − slant)/(n + 1)`, line `(L, y + slant/2)–(R, y − slant/2)`. All y stay inside `[FT, side_end]`.
3. Diameter dimension (`Dim`): extension lines `(L, side_end + 2)–(L, 274)` and `(R, side_end + 2)–(R, 274)`;
   dimension line `(L,268)–(R,268)`; arrows at both ends pointing outwards onto the extension lines
   (triangle tip on the extension line, length 6, half width 2.5), i.e. `[(L,268),(L+6,265.5),(L+6,270.5)]` and the
   mirror at R. Label `Diameter <fmt_len(diameter)>` at `(X, 286)`, `CenterCenter`.
4. Flute length dimension (`Dim`): extension lines `(R+2, FT)–(146, FT)` and `(xb + 2, TIP)–(146, TIP)` with
   `xb = R` for FlatEndMill else `X`; dimension line `(140,FT)–(140,TIP)`, arrows `[(140,FT),(137.5,FT+6),(142.5,FT+6)]`
   and the mirror at TIP. Label `Flute length\n<fmt_len(flute_length)>` at `(148, (FT+TIP)/2)`, `LeftCenter`.
5. Flutes: label `Flutes <flutes>` (true value, e.g. `Flutes 8`) at `(148, 50)`, `LeftCenter`; if `n > 0` a `Dim`
   leader from `(146, 50)` to the right end of the first hint line `(R, y₁ − slant/2)`.
6. V angle (VBit only): `Dim` arc centre (X,TIP), radius 20, from the left V edge direction to the right one through
   straight up (screen angles: from `−π/2 − a/2` to `−π/2 + a/2`, 12 segments, 13 points); label
   `V angle\n<v>°` (two lines) with `v = format!("{:.1}", angle_deg)` and a trailing `.0` stripped (`60°`, `59.5°`)
   at `(56, TIP − 12)`, `RightCenter`. The label text is the **true** angle, not the clamped one. Two lines because
   one line did not fit the ~56 pt between the box edge and the V edge (it was clipped by the 12 pt gap to the form);
   `summary()` turns it into `V angle 60°`.
   NaN `angle_deg` (not possible from the form or serde) is drawn as 60° before the clamp, so the body stays finite.

`bad`: Diameter `!(d.is_finite() && d > 0)`, FluteLength the same for `flute_length`, Flutes `flutes == 0`,
VAngle never.

Labels per kind: Flat / Ball / Drill → `[Diameter, FluteLength, Flutes]`; VBit → `[Diameter, FluteLength, Flutes, VAngle]`.

## `paint`
```rust
let (r, painter) = ui.allocate_painter(egui::vec2(SKETCH_W, SKETCH_H), egui::Sense::hover());
let o = r.rect.min; let at = |p: P| o + egui::vec2(p[0], p[1]);
```
Body: `Shape::convex_polygon(points, fill, Stroke(1.5, outline))`; each polyline `Shape::line(points, stroke(pen))`;
each arrow `Shape::convex_polygon(.., dim colour, Stroke::NONE)`; each label `painter.text(at(pos), align, text,
FontId::proportional(12.0), colour)` with `Anchor` → `Align2::LEFT_CENTER / RIGHT_CENTER / CENTER_CENTER`.
Then `r.widget_info(|| egui::WidgetInfo::labeled(egui::Role::Image, true, s.summary()))` and return `r`.
No painting outside `r.rect` is needed (all points are inside the box by construction).

## Risks
- **Accessibility node of a hover-only painter**: if egui 0.37 does not emit an accesskit node for
  `allocate_painter` + `widget_info`, use `ui.allocate_response(size, Sense::hover())` + `ui.painter_at(rect)`
  instead (same result). Do not add a hidden label as a workaround.
- **Window width**: egui windows remember their size per id; an old `default_width` only matters for a fresh
  memory (tests, screenshots). If the content is wider the window grows; check the screenshot for clipping.
- **`horizontal_top` + Grid**: the grid keeps its column layout inside a horizontal; if the Name / Comment text
  edits stretch to the available width and squeeze the sketch, give them `.desired_width(240.0)` (no other change).
- Light/dark: only `ui.visuals()` colours; the screenshot is light only; check dark once by eye
  (`Harness::builder().with_theme(egui::Theme::Dark)` locally, not committed).
